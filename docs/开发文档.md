# 开发文档

单 GPU 的数据清洗配置微调工程：中文需求 → 严格 JSON → 固定本地执行器。开发环境为 Python 3.12，当前基础模型为 1.5B，训练配置为 configs/train_4080.json。

## 当前模块

| 模块 | 职责 |
| --- | --- |
| cli.py | doctor、validate、prepare、train、chat、benchmark；默认使用 datasets/data_cleaning |
| data.py | JSONL 结构、ID/对话重复检查、group_id 分组划分 |
| encoding.py | 原生聊天模板、assistant-only 标签、动态 padding、超长过滤 |
| training_config.py | 配置校验、跨集合污染、数据哈希、完整恢复检查 |
| training.py | CUDA/BF16、缓存与固定快照、QLoRA、日志、检查点、单次推理 |
| data_cleaning.py | 四种配置操作的严格解析、类型校验与本地解释执行 |
| prediction.py | 独立进程批量生成，只读取题面与训练 system 提示，保存原始回答和生成清单 |
| data_cleaning_benchmark.py | 先测试后验证，分别比较微调/基础模型；核对来源、严格/诊断评分并调度 Excel 导出 |
| data_cleaning_example.py | generate_config、clean_rows 及可直接运行的单次使用示例 |
| paths.py | 项目根目录与基础模型缓存定位 |

## 脚本

scripts/benchmark_data_cleaning.py 是一键入口，scripts/export_data_cleaning_comparison.mjs 使用 Codex 附带 artifact-tool 生成 Excel。scripts/predict_eval.py 保留为批量预测入口，scripts/score_data_cleaning.py 做严格参考配置评分，scripts/plot_training.py 绘制训练日志。构建与有限执行检查分别由 build_data_cleaning.py、check_data_cleaning_cases.py 完成。

一键入口使用独立进程依次加载模型，避免同时占用 GPU。复用模式不加载模型，必须核对完整题面、预测与生成清单。输出目录拒绝覆盖，失败记录阶段，只有成功导出 Excel 才标 completed。Excel 有汇总、验证逐题、测试逐题三张表，汇总公式必须与比较数据一致，原始回答不改写。

## 数据与评估契约

当前训练/测试/验证为 1,000/200/200；完整来源每集 1,000 条。模型直接编写需求与答案，代码只序列化、抽样和检查，不调用模型 API 生成数据。来源、语义抽查与执行状态真实记录，自动检查不标人工审核。

只允许去重、空值处理、筛选和排序。输入数据不发给模型；模型只接收中文需求和 system 提示。非法回答停止执行，不修补成固定答案。详细 schema 见 datasets/data_cleaning/配置约定.md。

严格评分要求直接输出匹配参考的 JSON；诊断仅去掉完整包裹回答的一个 JSON 代码块。两者分开，均不是执行结果正确率。test 不参与训练损失或检查点选择，执行先后不改变 test/validation 的用途。

## 检查与保留范围

```powershell
python -m unittest discover -s tests -v
python scripts/check_data_cleaning_cases.py
```

测试覆盖格式、划分、配置/恢复、固定执行器、模型使用示例、来源核对、串行预测与失败状态，不默认进行 GPU 训练。依赖 versions 固定在 pyproject.toml。当前脚本的操作命令见[数据清洗数据集指南](数据清洗数据集指南.md)，文件保留规则见[项目文件与归档说明](项目文件与归档说明.md)。
