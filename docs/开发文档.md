# 开发文档

## 当前实现

单 GPU、命令行的 Python 编程助手 SFT 工程。原生 Windows、Python 3.12、RTX 4060、0.5B 模型已实测；4080 SUPER 与 1.5B 配置仍是待验证实验起点。

默认数据为 2,292/129/123 条训练/验证/问答留出样本，新增上游答案为静态检查状态。另有独立的 20 题、100 个本地用例执行子集。训练成功、验证损失改善和实际代码通过率必须分开报告。

## 配置与训练契约

使用 configs 下的扁平 JSON，不接受设计示意 YAML。smoke_4060 为 512 token、rank 8、10 步；train_4060 为 2048 token、rank 8、梯度累积 4、2 轮；train_4080 为 1.5B 的未实测配置。

固定策略为 micro batch 1、NF4 4-bit、双重量化、BF16、梯度检查点、AdamW、余弦学习率、梯度裁剪、仅更新 LoRA，不启用 packing。可配学习率、轮数/总步数、LoRA 目标/秩/dropout、warmup、weight decay、评估/保存间隔与数量。save_steps 必须为 eval_steps 的整数倍。未知字段、错误类型与非有限配置拒绝执行。

启动前校验 train/validation/test 的结构与跨集合污染，只对前两个编码；test 不参与损失或选择检查点。system/user 和 pad 标签屏蔽为 -100，仅 assistant 输出参与监督。模板无法校验前缀时拒绝训练。

缓存优先解析 revision 到固定 SHA，恢复与推理使用清单 SHA，不信任远程自定义代码。--offline 同时约束模型加载和 PEFT 保存。

## 恢复与产物

每次新实验使用新目录，训练锁防止同目录并行写入。run_manifest.json 保存实际配置、模型/模板和数据 SHA、版本、GPU、种子、编码统计、代码提交与脏状态；training_log.jsonl 记录日志；run_status.json 记录状态；metrics.json 是最近一次运行段的汇总。

--stop-after 在指定全局优化器步数保存后停止。正常结束也额外验证和保存，短于默认间隔仍有完整 checkpoint。结束后 Trainer 重载最佳已保存检查点，再评估并导出 adapter/，不合并基础权重。

完整恢复要求同一目录、配置、数据 SHA、依赖版本，以及适配器、优化器、调度器、随机状态和 Trainer 状态。adapter/ 不能代替完整 checkpoint；不能改动数据或延长已完成计划后恢复。

outputs 保留模型、checkpoint 和本地运行；reports 仅提交选定的日志、清单、预测和可选报告。export_experiment.py 检查文件关系和 SHA，不复制权重或密钥；轻量归档不具备恢复训练或模型推理能力。

## 预测与执行评估

predict_eval.py 每批加载一次模型，只使用训练时 system 提示与冻结 prompt，不提供 tests 或参考答案。默认 greedy、最多 1024 token，保留原始回答、截断、耗时与来源哈希；--base 生成同一基础模型基线。训练数据 SHA 和题目 ID 检查不等同完整语义去污染。

evaluate 使用现成预测，默认每题 5 秒，可显式设为共同的 10 秒预算。全部本地用例通过才计为该题通过；缺答、提取失败、语法错误、执行异常和超时都计入分母。Docker 未启动、镜像缺失属于环境错误，不计作模型失败。

执行器使用 Linux Docker、禁网、只读根目录、非 root、资源限制与独立临时目录。宿主只 compile 检查语法，不执行候选代码。本次归档时 Docker 引擎未运行，因此新 20 题只有完成的预测记录，没有执行通过率。
