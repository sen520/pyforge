# 项目文件与归档说明

## 当前主流程

本地 Python 3.12 环境 → 校验固定数据 → 从项目缓存加载模型 → QLoRA 训练 → 选择最佳已保存检查点 → 批量生成预测 → Docker 执行 → 归档轻量实验记录。

默认训练集 2,292 条、验证集 129 条、问答留出集 123 条。新增上游答案只做过静态检查；已执行的原始种子数据和未执行的参考答案不混淆审核状态。独立可执行算法子集是 20 题、100 个本地用例，排除在这次扩充训练划分之外。123 条问答尚无统一执行器。

## 脚本用途

| 脚本 | 作用 |
| --- | --- |
| build_leetcode_training.py | 当前 doocs 参考答案 SFT 构建；默认读取历史种子划分以保持其训练/验证分组 |
| predict_eval.py | 对冻结执行题批量生成基础或适配器预测，检查直接 ID 重叠与训练数据 SHA |
| plot_training.py | 散点、移动平均、分段均值趋势，支持运行日志或归档日志 |
| export_experiment.py | 检查完成状态和哈希，复制固定允许的轻量文件，不复制权重或密钥 |
| import_leetcode.py、build_eval_subset.py | 重建题面来源及固定执行子集 |
| make_question_bank.py、build_codex_data.py | 重建历史 100 题种子及 Codex 答案 |
| codex_solutions.py、codex_review_answers.py | 原始函数实现、修复、测试与解释答案源 |
| verify_codex_data.py、verify_teacher_data.py | 数据执行检查；共享用例和 Docker 检查器，仍有现有调用依赖 |
| evaluate_holdout.py | 只复跑归档的旧 5 题，不能拿来评估新的 123 条 |

`src/pyforge/generation.py`、generate CLI、对应测试及《教师数据生成指南》保留为历史兼容流程，不自动调用模型 API。不能仅因当前主流程未使用就删除依赖它们的可复现工具。

## 导出下一次实验

训练及预测完成后，用新归档路径：

```powershell
python scripts/export_experiment.py --run outputs/train-doocs-001 --output reports/train-doocs-001-copy --predictions outputs/doocs_finetuned_predictions_v1.jsonl
```

已有匹配的执行报告时，增加 `--evaluation outputs/doocs_finetuned_report_v1.json`。导出器检查预测完成状态、预测 SHA、训练清单 SHA、执行报告对应的预测与题库 SHA；存在的目录拒绝覆盖。归档不是 checkpoint，不包含推理所需的 adapter 权重。
