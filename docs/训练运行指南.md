# 训练运行指南

## 已实现的流程

训练采用 SFT + QLoRA：基础模型以 NF4 4-bit、双重量化加载，计算使用 BF16，仅更新 LoRA 参数。使用模型原生聊天模板，system 和 user 标签屏蔽为 `-100`，只计算 assistant 回答的损失。启用梯度检查点、梯度裁剪、余弦学习率与 warmup。

训练前检查配置、三个数据文件及跨集合 ID、group_id、完全相同对话。只对 train、validation 编码；超长样本整条过滤并记录数量，编码后为空时报错。test 不参与训练、检查点选择或损失计算。

模型优先从项目 `models/hub/` 缓存加载，将实际 commit SHA 写入运行清单；缓存缺失且未指定 `--offline` 时才下载。恢复与推理使用记录的 SHA。

## 本地开始

先激活 Python 3.12 环境，按[本地开发指南](本地开发指南.md)安装 CUDA PyTorch 和训练依赖。已下载模型后，在项目根目录运行：

```powershell
pyforge doctor
pyforge train --config configs/smoke_4060.json --output outputs/smoke-002 --offline
pyforge chat --run outputs/smoke-002 --offline --max-new-tokens 256 --prompt "编写一个判断偶数的 Python 函数"
```

`--data` 默认是 `datasets`。每次新实验使用新的输出目录，非空目录会被拒绝覆盖。`--offline` 同时约束基础模型加载与 PEFT 保存，缓存不完整时直接报错。量化训练与推理均要求 CUDA 和 BF16 支持。

4060 配置使用 0.5B 模型、最长 512 token、rank 8、micro batch 1、梯度累积 4、10 个优化器更新步；每 5 步评估并保存。正整数 `max_steps` 优先于 `epochs`，`-1` 表示按轮次运行。

4080 SUPER 实验使用以下命令；该硬件与 1.5B 配置尚未实测：

```powershell
pyforge train --config configs/train_4080.json --output outputs/train-001 --offline
```

请先下载对应的 1.5B 模型。当前只有 90 条训练样本，适合验证流程，正式训练前仍需扩充并审核数据。

## 暂停与完整恢复

需要验证恢复时，用 `--stop-after` 在指定的**全局优化器步数**保存完整检查点后停止，不改变原计划和学习率曲线：

```powershell
pyforge train --config configs/smoke_4060.json --output outputs/resume-001 --offline --stop-after 2
pyforge train --config configs/smoke_4060.json --output outputs/resume-001 --offline --resume outputs/resume-001/checkpoint-2
```

恢复需要同一输出目录、原配置、字节一致的数据和相同训练依赖版本。检查点必须包含适配器、优化器、调度器、随机状态及 Trainer 状态。恢复后会跳过已消费的数据并续接步数。配置或数据变化会被拒绝；达到计划总步数的检查点不能继续恢复，请另开实验。

意外中断后，可使用最近一次完整的 `checkpoint-N` 恢复；尚未保存的步骤需要重跑。强制结束进程可能留下 `.training.lock`，确认没有其他训练进程使用该目录后才能手动删除锁。已有进程运行时不要删除它。

## 输出与检查点选择

| 路径 | 用途 |
| --- | --- |
| `run_manifest.json` | 配置、模型 SHA、依赖、GPU、数据哈希、编码统计、代码提交与脏工作区标记 |
| `run_status.json` | loading / training / stopped / completed / failed / interrupted 状态 |
| `training_log.jsonl` | 逐次训练、验证日志；恢复时追加 |
| `metrics.json` | 最近一次运行段的训练指标、最终验证损失、最佳检查点和 PyTorch 峰值显存 |
| `trainer_state.json` | Trainer 最终状态 |
| `checkpoint-N/` | 对应步骤的适配器和完整恢复状态 |
| `adapter/` | 本次结束时验证损失最低的已保存适配器，以及 tokenizer、模板 |

正常结束及 `--stop-after` 都会额外评估并保存，短于默认保存间隔也有检查点。默认保留限制为 2，Trainer 可能同时保留最佳和最新检查点。`adapter/` 用于推理，恢复训练应传 `checkpoint-N/`。默认不合并基础权重。

离线保存时，PEFT 可能提示无法查询 Hub 上的基础模型 config，假定词表未修改；本流程没有新增 token，已验证适配器保存与重载。该提示不代表需要联网。

恢复后的 `metrics.json` 中运行时间、训练损失等来自最近一次运行段，不是各段的汇总；完整历史见 `training_log.jsonl`。显存数值只统计 PyTorch 当前进程，桌面及其他程序占用需另看 `nvidia-smi`。

## 配置与验证边界

配置采用 JSON，示例见 `configs/`。可调整 LoRA dropout、目标模块、保存/评估间隔、保留数量、warmup、weight decay 和梯度裁剪；其余默认值在 `training_config.py`。保存间隔必须是评估间隔的整数倍。类型错误、非有限数值和未知字段会在加载模型前被拒绝。

实测记录见[训练验证记录](训练验证记录.md)。训练损失不能代替代码执行通过率；尚需对原始模型和适配器使用同一冻结题集进行效果比较。
