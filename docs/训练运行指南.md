# 训练运行指南

当前数据已修复 57 条题面主接口。请使用新输出目录从基础模型开始训练；不能使用修复后数据恢复旧 train-doocs-001 检查点。当前哈希见 datasets/leetcode/metadata/current_manifest.json，修复与旧模型评估说明见[训练数据审计](训练数据审计.md)。

## 已实现的流程

训练采用 SFT + QLoRA：基础模型以 NF4 4-bit、双重量化加载，计算使用 BF16，仅更新 LoRA 参数。使用模型原生聊天模板，system 和 user 标签屏蔽为 `-100`，只计算 assistant 回答的损失。启用梯度检查点、梯度裁剪、余弦学习率与 warmup。

训练前检查配置、三个数据文件及跨集合 ID、group_id、完全相同对话。只对 train、validation 编码；超长样本整条过滤并记录数量，编码后为空时报错。test 不参与训练、检查点选择或损失计算。

模型优先从项目 `models/hub/` 缓存加载，将实际 commit SHA 写入运行清单；缓存缺失且未指定 `--offline` 时才下载。恢复与推理使用记录的 SHA。

## 本地开始

先按[本地开发指南](本地开发指南.md)安装 CUDA PyTorch 和训练依赖。首次运行可用正式配置在第 2 步保存后暂停，检查训练与推理链路，再从同一检查点恢复完整计划：

```powershell
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/preflight-4080-001 --offline --stop-after 2
pyforge chat --run outputs/preflight-4080-001 --offline --max-new-tokens 256 --prompt "编写一个判断偶数的 Python 函数"
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/preflight-4080-001 --offline --resume outputs/preflight-4080-001/checkpoint-2
```

这不是独立的 2 步训练配置；恢复后将完成原定 2 轮。停止时会额外验证整个验证集。正式运行也可直接使用下一节命令。

`--data` 默认是 `datasets/leetcode`。每次新实验使用新的输出目录，非空目录会被拒绝覆盖。`--offline` 同时约束基础模型加载与 PEFT 保存，缓存不完整时直接报错。量化训练与推理均要求 CUDA 和 BF16 支持。

## 训练、验证与测试命令速查

以下命令在项目根目录、已激活虚拟环境的 PowerShell 中执行。输出目录和报告文件必须使用尚不存在的新名称；下方 `train-4080-001` 是示例，请替换为自己的运行目录。

### 1. 数据格式与环境检查

```powershell
pyforge doctor
pyforge validate datasets/leetcode/train.jsonl
pyforge validate datasets/leetcode/validation.jsonl
pyforge validate datasets/leetcode/test.jsonl
```

`validate` 只检查数据格式及文件内重复，不运行模型、不计算验证损失或代码正确率。跨集合泄漏检查由 `train` 启动时统一执行。

### 2. 连续训练多个轮次

当前 4080 SUPER 正式配置已设置 `epochs=2`、`max_steps=-1`，直接运行：

```powershell
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/train-4080-001 --offline
```

当前数据为 2,292 条训练、129 条验证、123 条问答留出。若调整轮数，先复制配置到新的英文文件名，只对新实验修改；正整数 `max_steps` 会覆盖轮数。已有实验恢复必须使用原配置与数据。4060 小规模测试可使用 `configs/smoke_4060.json` 配合 `datasets/leetcode/archive/codex_v1`，512 token 配置不适合完整新增数据。

### 3. 查看验证结果

验证在训练过程中自动执行，没有单独的 `pyforge validation` 命令。当前 4080 正式配置每 100 步计算 `validation.jsonl` 的损失，结束时再次评估，并导出最佳已保存适配器。

```powershell
# 结束状态与最终指标
Get-Content outputs/train-4080-001/run_status.json
Get-Content outputs/train-4080-001/metrics.json

# 历次验证损失，可观察是否持续改善或开始回升
Get-Content outputs/train-4080-001/training_log.jsonl | ForEach-Object { ConvertFrom-Json $_ } | Where-Object { $null -ne $_.eval_loss } | Select-Object step, epoch, eval_loss
```

`best_checkpoint` 指向最佳已保存检查点，`adapter/` 已导出它的权重。训练批次的 `loss` 会波动，比较检查点时主要观察同一验证集的 `eval_loss`。新验证集有 129 条，其损失不能与旧 5 条验证集的数值直接比较；损失下降也不能代替执行正确率。

训练中或结束后，可以把已落盘日志画成散点图，不加载模型、不占用 GPU：

```powershell
python -m pip install -e ".[plot]"
python scripts/plot_training.py outputs/train-4080-001
# 保留原始散点，并为 loss、grad_norm 叠加 20 个记录点的移动平均
python scripts/plot_training.py outputs/train-4080-001 --window 20 --output outputs/train-4080-001/plots/training_trend.png
# 更清楚的 loss 趋势图，默认保存 plots/loss_trend.png
python scripts/plot_training.py outputs/train-4080-001 --style trend --window 20
```

也可直接传 `training_log.jsonl` 文件。默认输出 `plots/training_scatter.png`，包含 loss（同图标出 eval_loss）、裁剪前梯度范数、学习率、epoch 四幅散点图，横轴为优化器更新步数。支持 PNG/SVG/PDF 和 `--dpi`。缺少指标时显示空图；还未完成第一次验证时没有验证散点。运行期间反复执行会更新图片，读取到未写完的末行时忽略该行并提示；不会修改日志。恢复训练导致步数回退时去除旧分支的后续点，同一步同一指标采用最后一次记录。

`--style trend` 专门突出 loss：灰色细线保留原始训练值，蓝色粗线连接每 20 个记录点的非重叠分段平均，红色方点连线为未平滑的验证损失。末尾不足一个窗口的均值用空心菱形单独标出，不与完整分段混为一谈。`--window` 可调整分段大小；此模式省略梯度、学习率和 epoch 面板，以便集中观察损失。平均趋势只帮助观察训练，不能代替代码正确率。

### 4. 测试实际回答

```powershell
pyforge chat --run outputs/train-4080-001 --offline --max-new-tokens 512 --prompt "编写一个 Python 函数，移除列表中的重复元素并保持原顺序，说明输入限制并给出边界条件测试。"
```

这是单题推理检查，不是完整测试集评估。输出达到 token 上限可能被截断，应检查代码块是否完整。

### 5. 独立算法题执行评估

确定训练配置、检查点和生成规则后，再用冻结题集比较基础模型与微调模型。当前 `evaluate` 支持带测试用例的独立算法题库，不直接支持普通问答格式的 `datasets/leetcode/test.jsonl`。新 123 条留出题尚无统一执行器，不应拿参考答案相似度当代码正确率。历史 5 道留出题现已存档，可使用专用脚本复跑旧模型：

```powershell
python scripts/evaluate_holdout.py generate --run outputs/train-002 --output outputs/holdout-train-002-v1 --max-new-tokens 512
python scripts/evaluate_holdout.py score --run outputs/train-002 --output outputs/holdout-train-002-v1
Get-Content outputs/holdout-train-002-v1/base_report.json
Get-Content outputs/holdout-train-002-v1/finetuned_report.json
```

`generate` 要求本地 GPU 与模型缓存，分别禁用和启用同一适配器，用相同题面、tokenizer、基础模型 SHA、贪心生成参数进行比较，只提供 system/user 消息。原始预测逐题保存，记录生成长度和是否被截断。输出目录不能已存在；报告也拒绝覆盖。测试集哈希必须与训练清单一致。

`score` 要求 Docker Linux 引擎及已有的 `pyforge-eval:py312-pytest835` 镜像（镜像准备见[答案编写与检查指南](答案编写与检查指南.md)）。只在容器中执行生成代码，先以参考实现自检环境；函数题复用已有独立用例，pytest 生成题要求正确实现通过且能发现预设错误实现。不修改生成答案，多个代码块或语法错误按失败记录。该脚本默认读取 `datasets/leetcode/archive/codex_v1/test.jsonl`，仅适配历史 5 题，不适用于扩充后的 123 题，也不计算测试损失。

如果评估独立的 20 道算法题，先按[算法评估运行指南](算法评估运行指南.md)准备 UTF-8 JSONL 预测文件，每行包含题目 `id` 和模型原始 `response`。只能给模型题库中的 `prompt`，不能提供 `tests` 或参考答案；基础模型和微调模型使用相同生成规则，不手工修正答案。下面的命令不会自动生成预测，需先准备好对应文件：

```powershell
docker pull python:3.12-slim
pyforge evaluate --suite datasets/leetcode/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/base_predictions.jsonl --report outputs/base_report.json
pyforge evaluate --suite datasets/leetcode/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/finetuned_predictions.jsonl --report outputs/finetuned_report.json
Get-Content outputs/base_report.json
Get-Content outputs/finetuned_report.json
```

Docker Desktop 需已启动并使用 Linux 容器。报告中的 `pass_at_1` 是本地用例通过率，不是验证损失。缺答会计入总题数；用于反复调参的题集不应继续充当最终留出测试集。

## 暂停与完整恢复

需要验证恢复时，用 `--stop-after` 在指定的**全局优化器步数**保存完整检查点后停止，不改变原计划和学习率曲线：

```powershell
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/resume-4080-001 --offline --stop-after 2
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/resume-4080-001 --offline --resume outputs/resume-4080-001/checkpoint-2
```

恢复需要同一输出目录、原配置、字节一致的数据和相同训练依赖版本。检查点必须包含适配器、优化器、调度器、随机状态及 Trainer 状态。恢复后会跳过已消费的数据并续接步数。配置或数据变化会被拒绝；达到计划总步数的检查点不能继续恢复，请另开实验。

意外中断后，可使用最近一次完整的 `checkpoint-N` 恢复；尚未保存的步骤需要重跑。强制结束进程可能留下 `.training.lock`，确认没有其他训练进程使用该目录后才能手动删除锁。已有进程运行时不要删除它。

## 输出与检查点选择

可提交的轻量记录与完整 checkpoint 分开保存：历史 4060 完整运行已归档到 [reports/train-doocs-001](../reports/train-doocs-001/实验说明.md)。可使用 `python scripts/export_experiment.py --run outputs/运行目录 --output reports/新归档目录 --predictions outputs/预测.jsonl` 导出，有对应执行报告时增加 `--evaluation`。输出目录拒绝覆盖，检查文件哈希；不复制模型、优化器和密钥。目录说明见[项目文件与归档说明](项目文件与归档说明.md)。

| 路径 | 用途 |
| --- | --- |
| `run_manifest.json` | 配置、模型 SHA、依赖、GPU、数据哈希、编码统计、代码提交与脏工作区标记 |
| `run_status.json` | loading / training / stopped / completed / failed / interrupted 状态 |
| `training_log.jsonl` | 逐次训练、验证日志；恢复时追加 |
| `metrics.json` | 最近一次运行段的训练指标、最终验证损失、最佳检查点和 PyTorch 峰值显存 |
| `trainer_state.json` | Trainer 最终状态 |
| `checkpoint-N/` | 对应步骤的适配器和完整恢复状态 |
| `adapter/` | 本次结束时验证损失最低的已保存适配器，以及 tokenizer、模板 |

正常结束及 `--stop-after` 都会额外评估并保存，短于默认保存间隔也有检查点。默认保留限制为 2，Trainer 可能同时保留最佳和最新检查点。`adapter/` 用于推理，恢复训练应传 `checkpoint-N/`。默认不合并基础权重。

离线保存时，PEFT 可能提示无法查询 Hub 上的基础模型 config，假定词表未修改；本流程没有新增 token，已验证适配器保存与重载。该提示不代表需要联网。

恢复后的 `metrics.json` 中运行时间、训练损失等来自最近一次运行段，不是各段的汇总；完整历史见 `training_log.jsonl`。显存数值只统计 PyTorch 当前进程，桌面及其他程序占用需另看 `nvidia-smi`。

## 配置与验证边界

配置采用 JSON，示例见 `configs/`。可调整 LoRA dropout、目标模块、保存/评估间隔、保留数量、warmup、weight decay 和梯度裁剪；其余默认值在 `training_config.py`。保存间隔必须是评估间隔的整数倍。类型错误、非有限数值和未知字段会在加载模型前被拒绝。

实测记录见[训练验证记录](训练验证记录.md)。训练损失不能代替代码执行通过率；尚需对原始模型和适配器使用同一冻结题集进行效果比较。
