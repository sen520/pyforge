# 训练运行指南

## 已实现的流程

训练采用 SFT + QLoRA：基础模型以 NF4 4-bit、双重量化加载，计算使用 BF16，仅更新 LoRA 参数。使用模型原生聊天模板，system 和 user 标签屏蔽为 `-100`，只计算 assistant 回答的损失。启用梯度检查点、梯度裁剪、余弦学习率与 warmup。

训练前检查配置、三个数据文件及跨集合 ID、group_id、完全相同对话。只对 train、validation 编码；超长样本整条过滤并记录数量，编码后为空时报错。test 不参与训练、检查点选择或损失计算。

模型优先从项目 `models/hub/` 缓存加载，将实际 commit SHA 写入运行清单；缓存缺失且未指定 `--offline` 时才下载。恢复与推理使用记录的 SHA。

## 本地开始

先激活 Python 3.12 环境，按[本地开发指南](本地开发指南.md)安装 CUDA PyTorch 和训练依赖。已下载模型后，在项目根目录运行：

```powershell
pyforge doctor
pyforge train --config configs/smoke_4060.json --output outputs/smoke-002 --offline
pyforge chat --run outputs/smoke-002 --offline --max-new-tokens 256 --prompt "编写一个判断偶数的 Python 函数"
```

`--data` 默认是 `datasets`。每次新实验使用新的输出目录，非空目录会被拒绝覆盖。`--offline` 同时约束基础模型加载与 PEFT 保存，缓存不完整时直接报错。量化训练与推理均要求 CUDA 和 BF16 支持。

## 训练、验证与测试命令速查

以下命令在项目根目录、已激活虚拟环境的 PowerShell 中执行。输出目录和报告文件必须使用尚不存在的新名称；下方 `train-003` 是示例，请替换为自己的运行目录。

### 1. 数据格式与环境检查

```powershell
pyforge doctor
pyforge validate datasets/train.jsonl
pyforge validate datasets/validation.jsonl
pyforge validate datasets/test.jsonl
```

`validate` 只检查数据格式及文件内重复，不运行模型、不计算验证损失或代码正确率。跨集合泄漏检查由 `train` 启动时统一执行。

### 2. 连续训练多个轮次

先在 `configs/smoke_4060.json` 中设置下面两项并保存，其余字段保留：

```json
"epochs": 5,
"max_steps": -1
```

```powershell
pyforge train --config configs/smoke_4060.json --data datasets --output outputs/train-003 --offline
```

当前 90 条训练数据、梯度累积 4 时，5 轮约为 115 个更新步。若 `max_steps` 是正整数，它会覆盖轮数设置；只做 10 步冒烟时可改成 `10`。修改配置仅用于新实验，已有实验恢复必须使用原配置。

### 3. 查看验证结果

验证在训练过程中自动执行，没有单独的 `pyforge validation` 命令。4060 配置每 5 步计算 `validation.jsonl` 的损失，结束时再次评估，并导出最佳已保存适配器。

```powershell
# 结束状态与最终指标
Get-Content outputs/train-003/run_status.json
Get-Content outputs/train-003/metrics.json

# 历次验证损失，可观察是否持续改善或开始回升
Get-Content outputs/train-003/training_log.jsonl | ForEach-Object { ConvertFrom-Json $_ } | Where-Object { $null -ne $_.eval_loss } | Select-Object step, epoch, eval_loss
```

`best_checkpoint` 指向最佳已保存检查点，`adapter/` 已导出它的权重。训练批次的 `loss` 会波动，比较检查点时主要观察同一验证集的 `eval_loss`。验证集当前只有 5 条，不能仅凭损失下降证明能力提高。

### 4. 测试实际回答

```powershell
pyforge chat --run outputs/train-003 --offline --max-new-tokens 512 --prompt "编写一个 Python 函数，移除列表中的重复元素并保持原顺序，说明输入限制并给出边界条件测试。"
```

这是单题推理检查，不是完整测试集评估。输出达到 token 上限可能被截断，应检查代码块是否完整。

### 5. 独立算法题执行评估

确定训练配置、检查点和生成规则后，再用冻结题集比较基础模型与微调模型。当前 `evaluate` 支持带测试用例的独立算法题库，不直接支持普通问答格式的 `datasets/test.jsonl`；当前也没有自动批量生成预测或单独计算留出集损失的 CLI。

先按[算法评估运行指南](算法评估运行指南.md)准备 UTF-8 JSONL 预测文件，每行包含题目 `id` 和模型原始 `response`。只能给模型题库中的 `prompt`，不能提供 `tests` 或参考答案；基础模型和微调模型使用相同生成规则，不手工修正答案。下面的命令不会自动生成预测，需先准备好对应文件：

```powershell
docker pull python:3.12-slim
pyforge evaluate --suite datasets/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/base_predictions.jsonl --report outputs/base_report.json
pyforge evaluate --suite datasets/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/finetuned_predictions.jsonl --report outputs/finetuned_report.json
Get-Content outputs/base_report.json
Get-Content outputs/finetuned_report.json
```

Docker Desktop 需已启动并使用 Linux 容器。报告中的 `pass_at_1` 是本地用例通过率，不是验证损失。缺答会计入总题数；用于反复调参的题集不应继续充当最终留出测试集。

### 6. 项目代码测试

```powershell
# 单元测试；默认跳过 Docker 集成项
python -m unittest discover -s tests -v

# 启用 Docker 集成测试；先准备上面的镜像
$env:PYFORGE_DOCKER_TESTS = "1"
try {
    python -m unittest discover -s tests -v
} finally {
    Remove-Item Env:PYFORGE_DOCKER_TESTS
}
```

这些测试检查项目实现与执行器，不代表模型回答通过测试。

4060 配置使用 0.5B 模型、最长 512 token、rank 8、micro batch 1、梯度累积 4；每 5 步评估并保存。总步数取决于当前配置：正整数 `max_steps` 优先于 `epochs`，`-1` 表示按轮次运行。首次 GPU 验证使用 10 步，随后已在本机完成 5 轮、115 步实验。

4080 SUPER 实验使用以下命令；该硬件与 1.5B 配置尚未实测：

```powershell
pyforge train --config configs/train_4080.json --output outputs/train-001 --offline
```

请先下载对应的 1.5B 模型。当前只有 90 条训练样本，适合验证流程，正式训练前仍需扩充并审核数据。

## 暂停与完整恢复

需要验证恢复时，用 `--stop-after` 在指定的**全局优化器步数**保存完整检查点后停止，不改变原计划和学习率曲线：

```powershell
pyforge train --config configs/smoke_4060.json --output outputs/resume-001 --offline --stop-after 2
pyforge train --config configs/smoke_4060.json --output outputs/resume-001 --offline --resume outputs/resume-001/checkpoint-2
```

恢复需要同一输出目录、原配置、字节一致的数据和相同训练依赖版本。检查点必须包含适配器、优化器、调度器、随机状态及 Trainer 状态。恢复后会跳过已消费的数据并续接步数。配置或数据变化会被拒绝；达到计划总步数的检查点不能继续恢复，请另开实验。

意外中断后，可使用最近一次完整的 `checkpoint-N` 恢复；尚未保存的步骤需要重跑。强制结束进程可能留下 `.training.lock`，确认没有其他训练进程使用该目录后才能手动删除锁。已有进程运行时不要删除它。

## 输出与检查点选择

| 路径 | 用途 |
| --- | --- |
| `run_manifest.json` | 配置、模型 SHA、依赖、GPU、数据哈希、编码统计、代码提交与脏工作区标记 |
| `run_status.json` | loading / training / stopped / completed / failed / interrupted 状态 |
| `training_log.jsonl` | 逐次训练、验证日志；恢复时追加 |
| `metrics.json` | 最近一次运行段的训练指标、最终验证损失、最佳检查点和 PyTorch 峰值显存 |
| `trainer_state.json` | Trainer 最终状态 |
| `checkpoint-N/` | 对应步骤的适配器和完整恢复状态 |
| `adapter/` | 本次结束时验证损失最低的已保存适配器，以及 tokenizer、模板 |

正常结束及 `--stop-after` 都会额外评估并保存，短于默认保存间隔也有检查点。默认保留限制为 2，Trainer 可能同时保留最佳和最新检查点。`adapter/` 用于推理，恢复训练应传 `checkpoint-N/`。默认不合并基础权重。

离线保存时，PEFT 可能提示无法查询 Hub 上的基础模型 config，假定词表未修改；本流程没有新增 token，已验证适配器保存与重载。该提示不代表需要联网。

恢复后的 `metrics.json` 中运行时间、训练损失等来自最近一次运行段，不是各段的汇总；完整历史见 `training_log.jsonl`。显存数值只统计 PyTorch 当前进程，桌面及其他程序占用需另看 `nvidia-smi`。

## 配置与验证边界

配置采用 JSON，示例见 `configs/`。可调整 LoRA dropout、目标模块、保存/评估间隔、保留数量、warmup、weight decay 和梯度裁剪；其余默认值在 `training_config.py`。保存间隔必须是评估间隔的整数倍。类型错误、非有限数值和未知字段会在加载模型前被拒绝。

实测记录见[训练验证记录](训练验证记录.md)。训练损失不能代替代码执行通过率；尚需对原始模型和适配器使用同一冻结题集进行效果比较。
