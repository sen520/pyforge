# 训练运行指南

当前任务为中文需求转 JSON 数据清洗配置，默认数据目录 datasets/data_cleaning，训练 1,000 条、测试 200 条、验证 200 条。完整日常命令见[数据清洗数据集指南](数据清洗数据集指南.md)。

## 配置和训练

configs/train_4080.json 使用 Qwen2.5-Coder-1.5B-Instruct、2048 token、NF4 4-bit、双重量化、BF16、LoRA rank 16/alpha 32、micro batch 1、梯度累积 16、学习率 1e-4、2 轮。当前数据共 126 个优化器更新步，进度条不是样本数。评估与保存默认每 100 步，结束时另行评估和保存。

```powershell
Set-Location E:\code\github\pyforge
.\.venv\Scripts\Activate.ps1
pyforge doctor
pyforge train --config configs/train_4080.json --data datasets/data_cleaning --output outputs/data-cleaning-003 --offline
```

输出目录必须是新目录。启动前检查配置、三个数据文件与跨集合 ID、group_id、重复对话。只对 train/validation 编码，test 不参与损失或检查点选择。超长样本整条过滤并计入清单；当前数据长度检查均通过。system/user 标签屏蔽为 -100，只计算 assistant JSON 的损失。

## 查看状态

```powershell
Get-Content outputs/data-cleaning-003/training_log.jsonl -Tail 10 -Wait
```

上面的命令持续等待，可在单独日志窗口按 Ctrl+C 结束查看，不代表停止另一个窗口的训练。

```powershell
Get-Content outputs/data-cleaning-003/run_status.json
Get-Content outputs/data-cleaning-003/metrics.json
python scripts/plot_training.py outputs/data-cleaning-003 --style trend --window 20
```

loss 下降代表对参考答案的拟合，不能直接换算为配置匹配率。评估使用同一题面的基础模型与微调模型对照，严格指标和去代码块外壳诊断分开报告。

## 正常暂停与恢复

新建暂停实验时，在全局第 2 步保存完整检查点后停止，再继续同一计划：

```powershell
pyforge train --config configs/train_4080.json --data datasets/data_cleaning --output outputs/data-cleaning-resume-001 --offline --stop-after 2
pyforge train --config configs/train_4080.json --data datasets/data_cleaning --output outputs/data-cleaning-resume-001 --offline --resume outputs/data-cleaning-resume-001/checkpoint-2
```

恢复需要同一输出目录、原配置、字节一致的数据与依赖版本。必须使用包含适配器、优化器、调度器、随机状态和 Trainer 状态的 checkpoint-N，不能从 adapter/ 恢复。已达到计划步数的运行不能改配置延长后继续恢复。意外中断只能从实际存在的完整检查点继续，未保存步骤会重跑；清理训练锁前先确认没有活跃训练进程。

## 模型文件

| 路径 | 用途 |
| --- | --- |
| run_manifest.json | 配置、基础模型固定 SHA、system 提示、数据哈希、环境和 GPU 信息；不是权重 |
| run_status.json | 当前运行状态，完成时为 completed |
| training_log.jsonl、metrics.json | 日志和最近运行段指标 |
| checkpoint-N/ | 完整训练恢复状态 |
| adapter/adapter_model.safetensors | 训练后的 LoRA 权重 |
| adapter/ 中的配置与 tokenizer | 推理配套文件，保留整个目录 |
| models/hub/ | 固定版本的基础模型权重缓存 |

推理需要基础模型缓存、完整 adapter/ 和运行清单，不能只复制 run_manifest.json。最终 adapter/ 导出验证损失最低的已保存检查点，不一定是最后一步。默认不合并基础权重。

当前验证与测试各 200 条；缩减前完整数据保留在 datasets/data_cleaning/archive/full_v1。绑定旧数据哈希的运行恢复时必须使用原数据目录，历史验证 loss 不能直接当作当前小集合的指标。
