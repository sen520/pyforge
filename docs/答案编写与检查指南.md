# 答案编写与检查指南

## 当前方案

不再使用硅基流动生成训练答案。`scripts/codex_solutions.py` 为直接编写的 85 道函数实现和修复答案；`scripts/codex_review_answers.py` 为直接编写的 8 道 pytest 测试和 7 道解释题答案。构建器只读取本地种子题和这些答案源文件，不读取 `.env`，不依赖任何模型接口。

题目来源仍为 `datasets/seed_questions.jsonl`，答案来源统一标为 `codex_authored_v1`，不能将历史服务端答案改标签冒充新答案。历史数据独立保留，不合并训练。代码、题目和作者清单的 SHA 支持溯源。

## 使用与复现

`data/codex_v1/` 已提交完整候选、训练集、验证集、留出集及执行报告，克隆后可直接训练。若要复现到新的临时目录：

```powershell
python scripts/build_codex_data.py --output outputs/codex_rebuild
docker build -f docker/evaluation.Dockerfile -t pyforge-eval:py312-pytest835 docker
python scripts/verify_codex_data.py --source outputs/codex_rebuild/candidates.jsonl
```

构建器拒绝覆盖非空目录。验证器只接受完整 100 题且来源为 codex_authored_v1 的输入，并要求运行镜像已存在。运行阶段禁网，镜像构建阶段仅安装 pytest，不调用模型服务。依赖实际版本和镜像记录可通过 Docker 镜像 ID 追溯；重新构建镜像不保证与旧镜像逐字节相同。

## 验证层级

- 85 道实现和修复题：沿用独立断言并补充 KMP、逆序对的穷举小输入检查，补充 Unicode 分词、重复下标及长十进制加法等回归用例。
- 8 道测试生成题：真正运行 pytest，而不是只编译；每组同时通过正确实现并拒绝一个指定的典型错误实现。这不代表已覆盖所有可能缺陷。
- 7 道解释题：审阅说明，并执行例子中的断言，确认闭包、共享列表、迭代器、浅拷贝、finally 和排序等演示结果。

每题使用独立的受限 Docker 容器，沿用非 root、禁网、只读根目录和资源限制。测试生成题的被测实现通过临时 solution 模块提供，pytest 文件写在容器临时目录。训练答案会明确说明将实现保存为 solution.py，避免读者缺失上下文。

测试使用 pytest 的 [parametrize](https://docs.pytest.org/en/stable/how-to/parametrize.html) 与 [tmp_path](https://docs.pytest.org/en/stable/how-to/tmp_path.html) 功能；它们只用于测试生成题的验证镜像，不是训练框架运行依赖。

运行结果保存为 verification.jsonl，校验摘要保存为 verification_manifest.json；数据文件 SHA 和分组数量保存在 dataset_manifest.json。只有执行通过的样本导出为 train/validation/test，自动执行不会将 human_review 改为 true。

## 范围与限制

100 道题均通过本项目的检查，并不意味着覆盖所有合法输入、性能和自然语言解释问题。验证和留出集合都只有 5 条，不能支持可靠的全面能力结论。后续扩容仍需增加独立题族，避免在同一批题上反复调整后高估收益。

答案中算法复杂度通常按算术操作次数描述，Python 大整数的实际位运算成本并非常数。具体训练长度以 encoding_report.json 为准；不能截断函数体来适配显存配置。
