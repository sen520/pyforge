# 本地开发指南

## 当前实现边界

源码与配置采用英文文件名，说明文档采用中文名。当前具备标准库实现的数据校验、精确重复检查、分组划分、assistant-only 标签构造，以及基于 Transformers Trainer 的 QLoRA 训练和适配器单次推理入口。

已实现 20 题 Docker 算法执行评估，详见《算法评估运行指南》。尚未实现近似去重、模型效果对比、自动最优检查点选择、多轮交互界面。正式训练配置表示实验起点，不代表已通过验收。`开发文档.md` 与 `数据与评估规范.md` 中未交付的内容仍为目标规范。

## Python 3.12 环境安装

虚拟环境由开发者准备。确认激活后 `python --version` 显示 3.12，并使用 `python -m pip` 安装，避免安装到其他解释器。

当前项目将 PyTorch 固定为 `2.6.0`，本机驱动 566.24 采用 CUDA 12.4 构建。版本声明本身不指定 CUDA 下载源，请先在虚拟环境中替换 CPU 版，再安装项目依赖：

```powershell
python -m pip uninstall -y torch
python -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
```

以上安装方式参见 [PyTorch 官方历史版本说明](https://docs.pytorch.org/get-started/previous-versions/)。`torch==2.6.0` 的声明允许已安装的 `2.6.0+cu124`；单独执行项目依赖安装不能保证获得 CUDA 构建。之后在仓库根目录执行：

```powershell
python -m pip install -e ".[train]"
python -m unittest discover -s tests -v
pyforge doctor
```

依赖范围定义在 `pyproject.toml`，当前尚未经过真实 GPU 兼容性验证，不能视为锁定环境。原生 Windows 若出现 bitsandbytes 或 CUDA 问题，先保存完整报错，再考虑使用 WSL2。不要因错误静默转用 CPU 训练。

## 4060 冒烟流程

模型权重和 tokenizer 默认缓存到项目下的 `models/hub/`，代码显式传入缓存路径，不需要设置 `HF_HUB_CACHE`。训练和推理使用同一目录；首次缺少文件会自动下载，已缓存文件会复用。路径根据源码位置确定，不随终端工作目录变化。当前采用仓库内 editable 安装（`pip install -e .`）。

若提前手动下载，在项目根目录执行下面命令，让文件进入相同缓存布局；不要改用 `--local-dir`，其目录布局不同：

```powershell
hf download Qwen/Qwen2.5-Coder-0.5B-Instruct --cache-dir D:/sen/pyforge/models/hub
```

```powershell
python scripts/make_demo_data.py data/demo.jsonl
pyforge validate data/demo.jsonl
pyforge prepare data/demo.jsonl data/prepared
pyforge train --config configs/smoke_4060.json --data data/prepared --output outputs/smoke-001
pyforge chat --run outputs/smoke-001 --prompt "编写一个 Python 函数，返回列表中的最大值"
```

示例生成器拒绝覆盖已有文件，数据划分拒绝覆盖非空目录。重新实验请使用新路径。示例的同类加法题仍然存在明显模板相似性，它们只用于流程测试，不用于模型能力比较。

4060 配置使用 Qwen2.5-Coder-0.5B-Instruct、4-bit NF4、512 token、LoRA rank 8、micro batch 1、累积 4 步、共 10 个优化器更新步。8 GB 是总显存，不保证当前剩余显存足够；遇到 OOM 时先减少其他 GPU 占用，再缩短 `max_length`。

训练时读取 train、validation、test 三个文件，只对前两个编码和计算损失。测试集在此阶段只检查格式、ID 和 group_id 交叉污染，不参与训练。超长样本过滤数量写入运行清单。

## 正式训练与恢复

准备有权使用且已审核的数据，生成独立划分，再执行：

```powershell
pyforge train --config configs/train_4080.json --data data/production --output outputs/train-001
```

`revision: main` 会在加载时解析为固定的模型 commit SHA，并记录在运行清单中；正式复现建议直接把 SHA 填入配置。每次运行使用不同输出目录。

完整恢复需要原配置、原数据、原输出目录以及包含优化器和调度器状态的 `checkpoint-N`：

```powershell
pyforge train --config configs/smoke_4060.json --data data/prepared --output outputs/smoke-001 --resume outputs/smoke-001/checkpoint-5
```

上面的检查点路径仅为示例，请替换为实际生成的目录。默认每 100 步保存，结束时额外保存完整检查点，因此 10 步冒烟运行通常仅有结束检查点。恢复已达到 `max_steps` 的结束检查点不会再增加训练步数；当前严格核对配置，不支持通过改配置延长已完成的运行。

## 产物与验收

每次运行输出运行清单、训练指标、Trainer 状态、完整检查点及 `适配器/`。适配器推理重新使用记录的基础模型 SHA。量化推理同样需要 CUDA 与训练扩展依赖。

本轮开发的验收依次为：CPU 数据与编码测试通过；真实 tokenizer 前缀验证通过；GPU 反传及 loss 有限；适配器保存后在全新进程成功加载；完整检查点恢复通过。全部验证后导出环境版本清单，才将该组合标记为已验证。训练损失不构成 pass@1 或能力提升证据。
