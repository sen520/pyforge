# 本地开发指南

## 当前实现边界

源码与配置采用英文文件名，说明文档采用中文名。当前具备标准库实现的数据校验、精确重复检查、分组划分、assistant-only 标签构造，以及基于 Transformers Trainer 的 QLoRA 训练和适配器单次推理入口。

已实现 20 题 Docker 算法评估、基础/适配器批量预测、按验证损失选择最佳已保存检查点、日志绘图和轻量归档。完整语义近似去重、多轮界面和新 123 题统一执行器尚未实现。4060 的 2048 token、2 轮训练已完成；1.5B/4080 仍为待验证配置。

## Python 3.12 环境安装

当前工作目录为 `E:\code\github\pyforge`，先在 PowerShell 执行：

```powershell
Set-Location E:\code\github\pyforge
```

虚拟环境由开发者准备。确认激活后 `python --version` 显示 3.12，并使用 `python -m pip` 安装，避免安装到其他解释器。

当前项目将 PyTorch 固定为 `2.6.0`，历史 4060 实测环境采用驱动 566.24 与 CUDA 12.4 构建；当前 4080 SUPER 环境需用 `pyforge doctor` 核对。版本声明本身不指定 CUDA 下载源，请先在虚拟环境中替换 CPU 版，再安装项目依赖：

```powershell
python -m pip uninstall -y torch
python -m pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cu124
```

以上安装方式参见 [PyTorch 官方历史版本说明](https://docs.pytorch.org/get-started/previous-versions/)。`torch==2.6.0` 的声明允许已安装的 `2.6.0+cu124`；单独执行项目依赖安装不能保证获得 CUDA 构建。之后在仓库根目录执行：

```powershell
python -m pip install -e ".[train]"
python -m unittest discover -s tests -v
pyforge doctor
```

训练扩展依赖已在 `pyproject.toml` 固定为本机实测版本；已通过原生 Windows、4060 的训练、恢复与推理验证，详见[训练验证记录](训练验证记录.md)。原生 Windows 若出现 bitsandbytes 或 CUDA 问题，先保存完整报错，再考虑使用 WSL2。不要因错误静默转用 CPU 训练。

## 当前 4080 SUPER 首次运行

模型权重和 tokenizer 默认缓存到项目下的 `models/hub/`，代码显式传入缓存路径，不需要设置 `HF_HUB_CACHE`。训练和推理使用同一目录；首次缺少文件会自动下载，已缓存文件会复用。路径根据源码位置确定，不随终端工作目录变化。当前采用仓库内 editable 安装（`pip install -e .`）。

若提前手动下载，在项目根目录执行下面命令，让文件进入相同缓存布局；不要改用 `--local-dir`，其目录布局不同：

```powershell
hf download Qwen/Qwen2.5-Coder-1.5B-Instruct --cache-dir E:/code/github/pyforge/models/hub
```

```powershell
pyforge validate datasets/leetcode/train.jsonl
pyforge doctor
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/preflight-4080-001 --offline --stop-after 2
pyforge chat --run outputs/preflight-4080-001 --offline --prompt "编写一个 Python 函数，返回列表中的最大值"
```

旧加法示例已删除。当前 datasets 下有 2,292 条训练、129 条验证、123 条新留出问答；原始 100 条已存档，新增上游答案仅静态检查。来源与检查记录见 datasets/leetcode/数据集说明.md。当前 4080 SUPER 扩充数据使用 `configs/train_4080.json` 的 2048 token 配置，避免 512 token 冒烟配置大量过滤样本。重新构建数据或运行实验请使用新输出路径。

可选的 `smoke_4060.json` 冒烟配置使用 Qwen2.5-Coder-0.5B-Instruct（需另行下载该模型），采用、4-bit NF4、512 token、LoRA rank 8、micro batch 1、累积 4 步。`max_steps=10` 用于短冒烟；连续多轮训练设为 `-1` 并调整 `epochs`。完整训练、验证与测试命令见[训练运行指南](训练运行指南.md)。8 GB 是总显存，不保证当前剩余显存足够；遇到 OOM 时先减少其他 GPU 占用，再缩短 `max_length`。

训练时读取 train、validation、test 三个文件，只对前两个编码和计算损失。测试集在此阶段只检查格式、ID 和 group_id 交叉污染，不参与训练。超长样本过滤数量写入运行清单。

## 正式训练与恢复

当前 4080 SUPER（16 GB）配置为 1.5B、2048 token、rank 16 / alpha 32、micro batch 1、梯度累积 16、学习率 1e-4、2 轮，每 100 步评估和保存。该配置尚未完成 GPU 实测；当前数据的上游答案仅部分执行审计。使用现有划分正式训练：

```powershell
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/train-4080-001 --offline
```

`revision: main` 会在加载时解析为固定的模型 commit SHA，并记录在运行清单中；正式复现建议直接把 SHA 填入配置。每次运行使用不同输出目录。

完整恢复需要原配置、原数据、原输出目录以及包含优化器和调度器状态的 `checkpoint-N`：

```powershell
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/preflight-4080-001 --offline --resume outputs/preflight-4080-001/checkpoint-2
```

上面恢复首次运行在第 2 步暂停的目录，完成原定 2 轮计划；其他运行请替换为实际完整检查点。4060 配置每 5 步保存，正式配置默认每 100 步保存；结束时额外评估并保存完整检查点。已达到 `max_steps` 的检查点会被拒绝恢复；当前严格核对配置，不支持通过改配置延长已完成的运行。

## 产物与验收

每次运行输出运行清单、训练指标、Trainer 状态、完整检查点及 `adapter/`。适配器推理重新使用记录的基础模型 SHA。量化推理同样需要 CUDA 与训练扩展依赖。

本轮开发的验收依次为：CPU 数据与编码测试通过；真实 tokenizer 前缀验证通过；GPU 反传及 loss 有限；适配器保存后在全新进程成功加载；完整检查点恢复通过。上述链路已在 4060 上通过，版本与实测指标见[训练验证记录](训练验证记录.md)；暂停与恢复的完整示例见[训练运行指南](训练运行指南.md)。训练损失不构成 pass@1 或能力提升证据。
