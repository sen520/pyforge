## 首版范围

已从 doocs 验证候选集中冻结 20 道无需链表、二叉树或交互适配的算法题，共 100 个独立编写的测试用例。题面来源和许可保留在数据中。测试不是 LeetCode 官方隐藏测试，结果仅表示本地用例的单次生成通过率。

题库为 `datasets/leetcode/benchmarks/doocs-leetcode/executable_v1.jsonl`，清单为同名 `.manifest.json`。包含整数回文、盛水容器、三数之和、电话号码组合、括号生成、数独、字符串、数字计算及数组等任务。题库包含期望输出，模型输入只能使用 `prompt`，不能传 `tests`、参考实现或报告。

## 预测格式与运行

### 一键完成全流程

```powershell
pyforge benchmark --run outputs/train-doocs-001 --output outputs/benchmark-001
```

该入口依次向基础模型（不加载 LoRA）和微调模型发送相同 20 题，再以固定 Docker 镜像 ID 和相同预算执行两批答案，自动生成 comparison/逐题对比.md、逐题答案对比.html、comparison.json，并在终端打印表格。HTML 包含可展开的题面与两边完整回答；不是只生成单模型通过率。它不自动创建 xlsx，不需要电子表格依赖。

可选参数：--suite 自定义带用例题库、--data 原训练数据目录、--max-new-tokens 1024、--timeout 10、--image python:3.12-slim。启动前检查原数据 SHA、题目重叠、适配器与 Docker 镜像；预测子进程结束后才加载另一模型。不会联网调用模型 API，也不自动拉取 Docker 镜像。

输出目录必须不存在。pipeline_status.json 保存正在执行的阶段或失败原因；任何一步失败都停止，不输出假成功。暂不支持全流程断点恢复，保留的中间预测可通过分步命令继续执行和比较。

### 分步运行

对扩充数据训练后的 `train-doocs-001`，在项目根目录先批量生成 20 题答案，再执行 Docker 检查：

```powershell
python scripts/predict_eval.py --run outputs/train-doocs-001 --output outputs/doocs_finetuned_predictions_v1.jsonl
pyforge evaluate --suite datasets/leetcode/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/doocs_finetuned_predictions_v1.jsonl --report outputs/doocs_finetuned_report_v1.json --timeout 10
Get-Content outputs/doocs_finetuned_report_v1.json
```

可用相同参数生成基础模型基线，仅增加 `--base`，然后分别执行评估：

```powershell
python scripts/predict_eval.py --run outputs/train-doocs-001 --base --output outputs/doocs_base_predictions_v1.jsonl
pyforge evaluate --suite datasets/leetcode/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/doocs_base_predictions_v1.jsonl --report outputs/doocs_base_report_v1.json --timeout 10
```

脚本每批只加载模型一次，离线使用项目缓存；只把题目 prompt 和训练时的 system 提示发给模型。默认最多生成 1024 token，保留原始回答、截断标记和清单，拒绝覆盖旧输出。通过 `--data` 的训练集 SHA 与 ID 检查防止直接重复题，不能替代语义去污染。新旧模型必须使用相同生成长度与执行超时。`--limit` 仅用于调试，完整评估不应使用，否则缺答计为失败。

## 逐题对照表

两边对同一 20 题各生成一次并执行相同测试后，生成逐题结果表和完整答案对照：

```powershell
python scripts/compare_eval.py --base-predictions outputs/doocs_base_predictions_v1.jsonl --base-report outputs/doocs_base_report_v1.json --finetuned-predictions outputs/doocs_finetuned_predictions_v1.jsonl --finetuned-report outputs/doocs_finetuned_report_v1.json --output outputs/comparison-v1
```

预测文件旁必须有批量生成入口写入的同名 .manifest.json。比较器按 ID 对齐，拒绝重复、缺题或条件不一致；验证报告/预测/题库 SHA、模型 revision、训练清单 SHA、生成长度、采样开关、镜像和超时。输出目录须不存在。

- 逐题对比.md：20 行结果表，列出题目、基础模型状态、微调状态、改善/退步。
- 逐题答案对比.html：可展开题面及两边完整原始回答，HTML 转义防止答案作为页面代码执行。
- comparison.json：逐题状态、用例、token、原始回答、共同条件与来源 SHA。

改善表示基础未通过而微调通过，退步为反向变化；均未通过仍保留具体失败类别和用例计数，不强行排序不同失败类别。本轮已完成的对照存放于 reports/train-doocs-001/comparison/，另有 Excel，包含汇总公式、20 行结果和完整题面/答案。

实测基础模型 12/20、微调模型 10/20，2 题改善、4 题退步。应先报告配对差异，再分析原因；不能将不同题集的旧分数当作基线。样本只有 20 题，不足以推断整体编程能力。

以上是保留的 20 道可执行算法评估题，不是新增的 123 条问答留出集；后者尚无通用执行器。历史 `evaluate_holdout.py` 也不能直接用于新模型或新留出集。

每题一次生成，基础模型与微调模型使用相同题面、模板、贪心解码、最大生成长度和模型环境。UTF-8 JSONL 预测文件每行包含 id 和原始 response：

```json
{"id":"doocs-leetcode-0009","response":"```python\nclass Solution:\n    def isPalindrome(self, x: int) -> bool:\n        return str(x) == str(x)[::-1]\n```"}
```

模型输出唯一 Python 代码块，或整条回答仅含 Python 代码。多个代码块、未闭合代码块、语法错误均失败。保留原始输出，不手工修正。重复或未知预测 ID 会拒绝整批评估；缺答计入总题数。

```powershell
pyforge evaluate --suite datasets/leetcode/benchmarks/doocs-leetcode/executable_v1.jsonl --predictions outputs/base_predictions.jsonl --report outputs/base_report.json
```

报告路径必须不存在。默认每题全部测试共用 5 秒墙钟预算，包含容器启动时间，可用 `--timeout 10` 调整，两模型必须一致。`--image` 可指定其他本地 Python 3.12 镜像，评估不自动拉取镜像。

一道题全部用例通过才计为通过。三数之和允许内外顺序不同，字符串组合允许外层顺序不同，但多余重复结果仍失败。其他结果严格比较 JSON 类型和值，布尔值不能冒充整数。

报告记录题数、通过数、pass_at_1、逐题状态、题库和预测 SHA、实际镜像 ID 与时间限制。状态包括缺答、提取/语法失败、执行异常、超时、输出超限、格式错误、答案错误和通过。只验证本地函数结果，不保证渐进复杂度或所有输入正确；不能将 20 题结果代表全部 3,422 题或整体编程能力。

## 隔离边界

宿主不执行候选代码。每题使用新容器，禁网、只读根文件系统、非 root、去除 capabilities、禁止提权；CPU 为 1、内存和交换总额 256 MB、进程数 32。只读挂载本题临时代码和输入，不挂载期望答案、模型、仓库或密钥。临时目录上限 16 MB，捕获输出约 64 KB，超时显式删除容器。

Docker 是执行隔离边界，不是针对主动攻击评估器的完整安全证明。候选代码和结果协议在同一 Python 进程，尚未实现防伪造；本版本用于普通模型答案验证，不用于恶意代码竞赛。不能给容器挂载 Docker socket 或额外宿主目录。
