# 数据与评估规范

当前任务为中文需求转 JSON 数据清洗配置，操作仅包含去重、空值处理、筛选、排序。详细字段和空值/比较规则见[配置约定](../datasets/data_cleaning/配置约定.md)。

## 来源和划分

需求、列名、条件值、操作顺序与参考答案由 Codex 和获用户授权的三个子代理逐条编写；代码只保存、封装、抽样、计数和检查。不得用参数替换模板或循环拼接需求后标为直接编写，不调用付费模型 API 生成答案。

三个完整作者原稿各 1,000 条。当前训练保持 1,000 条；测试和验证分别按场景、操作序列固定抽取 200 条。原始 ID 与 source_line 保留，所以题号可能超过 200，不是运行计数。抽样方法和文件哈希见 datasets/data_cleaning/metadata/manifest.json。

场景族不得跨集合，检查 ID、完全对话与规范化题面重复，但不宣称已证明所有语义近似任务互不泄漏。test 不参与参数更新、loss 或检查点选择；validation 可用于开发与检查点选择。不能通过反复查看测试结果调参后仍宣称其是独立最终测试。

## 检查状态

来源真实记录，不把自动检查标为人工审核。格式/schema、列名引用、长度检查不等于中文需求语义已获证明。139 条语义抽查和 18 条独立执行用例对应完整原稿中的指定样本，不能外推到全部数据。历史硅基流动数据独立只读保留，不混入当前集合。

## 模型对比

使用相同题面、system 提示、基础模型 SHA、贪心生成规则和 token 上限分别生成未加载 LoRA 的基础模型预测与微调预测。只向模型提供 system/user，不提供 assistant 参考答案。保留原始回答、截断状态、题面与预测哈希，不手工修正后伪装成模型输出。

严格评分要求原始回答直接是合法配置且匹配参考答案，忽略对象键顺序与空白，保留数组顺序和值类型。代码块外壳不算严格通过。诊断评分仅去掉完整的一个 JSON 代码块外壳，再使用同一规则；不改写字段和值，不替代严格结果。

格式合格率、配置匹配率、参考配置执行检查、训练/验证 loss 是不同指标。配置匹配率不是执行结果正确率；低 loss 或单题通过不能代替测试集对比。完整一键入口和 Excel 使用方法见[数据清洗数据集指南](数据清洗数据集指南.md)。
