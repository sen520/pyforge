# 数据清洗数据集指南

当前方向是中文需求转固定 JSON 数据清洗配置，四种操作的规则见[配置约定](../datasets/data_cleaning/配置约定.md)，来源与划分见[数据集说明](../datasets/data_cleaning/数据集说明.md)。只生成配置，真实数据由固定程序处理。

## 1. 训练

当前训练 1,000 条、验证 200 条、测试 200 条。下面按顺序在同一个 PowerShell 窗口执行；重新打开窗口后，需要重新设置环境和目录变量。训练由你手动启动，训练命令正常结束后再开始导出题面和评估。

### 环境准备

```powershell
Set-Location E:\code\github\pyforge
.\.venv\Scripts\Activate.ps1

$runDir = "outputs/data-cleaning-002"
$evalDir = "outputs/data-cleaning-eval-002"

pyforge doctor
if ($LASTEXITCODE -ne 0) { throw "训练环境检查失败。" }
```

两个输出目录必须是新目录。已存在时更换编号，例如分别改成 `data-cleaning-003` 和 `data-cleaning-eval-003`，后面的命令共用这两个变量。中断的 `outputs/data-cleaning-001` 也不能当成已完成的运行。

### 训练命令

```powershell
pyforge train --config configs/train_4080.json --data datasets/data_cleaning --output $runDir --offline
if ($LASTEXITCODE -ne 0) { throw "训练未正常完成，请先检查报错。" }
```

当前 4080 SUPER 配置使用 1.5B 模型，从基础模型初始化新 LoRA，训练 2 轮、共 126 个优化器更新步。micro batch 为 1，梯度累积为 16，进度条不是样本计数。训练过程中会自动计算验证 loss；后面的验证和测试检查实际 JSON 答案。不要在训练仍进行时启动预测。

训练结束后可先查看指标：

```powershell
Get-Content -LiteralPath "$runDir/metrics.json"
```

## 2. 测试

已完成训练并激活虚拟环境后，在项目根目录执行：

```powershell
python scripts/benchmark_data_cleaning.py --run outputs/data-cleaning-002 --output outputs/data-cleaning-comparison-001
```

同一流程也可用 CLI 入口 `pyforge benchmark --run outputs/data-cleaning-002 --output outputs/data-cleaning-comparison-001`；两种入口选一种执行即可，输出目录必须使用新名称。

该命令不重新训练模型。它自动提取当前验证和测试题面，各 200 条；依次运行测试微调、测试基础、验证微调、验证基础四次离线预测，再评分并生成 `模型效果对比.xlsx`。两种模型在独立进程中顺序加载，无须 Docker 或付费 API。

如果已经按下文分步命令生成了四份预测，可以直接复用，不再加载模型或占用 GPU：

```powershell
python scripts/benchmark_data_cleaning.py --run outputs/data-cleaning-002 --reuse-predictions outputs/data-cleaning-eval-002 --output outputs/data-cleaning-comparison-002
```

复用目录需要包含以下文件：

| 类型 | 文件 |
| --- | --- |
| 两份题面 | `validation-prompts.jsonl`、`test-prompts.jsonl` |
| 验证预测 | `validation-base.jsonl`、`validation-finetuned.jsonl` |
| 测试预测 | `test-base.jsonl`、`test-finetuned.jsonl` |
| 四份生成清单 | 将各预测文件的 `.jsonl` 后缀替换为 `.manifest.json` |

脚本核对训练数据、模型快照、适配器、题面、预测哈希与生成条件，拒绝混用不同批次、缺答或中断的预测。复用时沿用原生成参数，不会修改原始预测或已有报告。

Excel 有三个工作表：效果汇总、验证集对比、测试集对比。逐题表可筛选、冻结题号与表头，包含完整需求、参考 JSON、两边原始回答、错误原因及改善/退步。这里“之前”指同一个 1.5B 基础模型未加载 LoRA，“现在”指 `--run` 中的微调适配器。

严格评分要求直接输出合法且匹配参考的 JSON；“去外壳诊断”只去掉完整包裹回答的一个 JSON 代码块，再用同一规则比较。两个口径分开显示，不把诊断替换成正式严格结果，也不把配置匹配率称作执行正确率。

输出目录还保留 `comparison.json`、每种模型的严格/诊断逐题评分和 `pipeline_status.json`。目录必须是新目录；失败会记录阶段，不能当作已完成。需要完整重跑时换新目录；只有四份预测均完成且条件一致时才能复用。

Excel 使用本机 Codex 附带的 Node.js 与 `@oai/artifact-tool`，无需在项目安装 npm 包。运行时会在输出目录建立依赖目录引用，生成预览并检查汇总公式，不安装或修改依赖。换机器缺少该运行时时，可通过 `--node` 和 `--artifact-modules` 指定已有可执行文件与包目录；缺少依赖会在预测前报错。

常见情况：

| 情况 | 处理 |
| --- | --- |
| 找不到 run_manifest.json | `--run` 必须指向实际存在且已完成的数据清洗训练目录 |
| 输出目录已存在 | 更换 `--output` 编号，不覆盖旧预测或报告 |
| 题号超过 200，例如 validation-0290 | 这是保留的原始 ID，不是已执行数量；每个集合仍只有 200 条 |
| 基础模型严格评分为 0 | 查看完整回答及诊断评分；代码块外壳也会导致严格格式失败，不能直接认定内容全错 |
| 预测或清单哈希不符 | 使用同一批完整原始文件，或换新目录重新生成；不要修改答案或清单来绕过检查 |

默认运行四次预测：测试微调、测试基础、验证微调、验证基础，各 200 条，共 800 条回答。最终以 `pipeline_status.json` 的 completed 和实际生成的 Excel 为完成依据。

选择一键脚本后，不必重复执行后面的手工题面导出和预测循环。

## 3. 验证

一键脚本完成测试集的两种模型预测与评分后，自动继续验证集的两种模型预测与评分，各 200 条，无需再执行验证命令。全部完成后在 --output 目录查看模型效果对比.xlsx。验证集用于开发评估，测试集用于最终对照；执行先后不改变集合用途。

训练期间的验证 loss 会自动计算；此处验证是训练结束后生成 JSON 并评分，两者不是同一指标。

## 4. 使用训练好的模型

示例脚本为 [src/pyforge/data_cleaning_example.py](../src/pyforge/data_cleaning_example.py)。激活项目虚拟环境后，在项目根目录运行：

```powershell
python -m pyforge.data_cleaning_example --run outputs/data-cleaning-002
```

默认需求是：先删除“邮箱”为 null 的行，再按“邮箱”去重保留最后一条，最后按“积分”降序。示例内置 5 行数据，包含空邮箱和重复邮箱。终端会显示模型加载日志，随后打印原始模型回答、校验后的配置、输入/输出行数与清洗结果。

只需要模型生成配置时：

```powershell
python -m pyforge.data_cleaning_example --run outputs/data-cleaning-002 --prompt '按“积分”降序排列。' --config-only
```

处理自己的数据时，先将 JSON 对象数组保存为 UTF-8 的 input.json，例如：

```json
[
  {"邮箱": "a@example.com", "积分": 50},
  {"邮箱": null, "积分": 99},
  {"邮箱": "b@example.com", "积分": 80},
  {"邮箱": "a@example.com", "积分": 90}
]
```

然后执行：

```powershell
python -m pyforge.data_cleaning_example --run outputs/data-cleaning-002 --input-json input.json --prompt '先删除“邮箱”为null的行，再按“邮箱”去重保留最后一条，最后按“积分”降序排列。'
```

输入文件不会被改写，清洗结果打印到终端。列名必须与需求一致；只支持约定中的去重、空值处理、筛选和排序。数据行留在本地执行器中，模型只接收中文需求与训练时的 system 提示。

在自己的 Python 程序中调用：

```python
from pyforge.data_cleaning_example import clean_rows

result = clean_rows(
    prompt='按“积分”降序排列。',
    rows=[{"积分": 10}, {"积分": 30}, {"积分": 20}],
    run='outputs/data-cleaning-002',
)
print(result['config'])
print(result['rows'])
```

底层复用 training.chat，加载训练记录中的固定基础模型 SHA、adapter/ 和 system 提示，默认严格离线。需要 CUDA、BF16 与训练依赖，不能只复制轻量报告后运行。模型若返回代码块、非法 JSON 或不支持的操作，示例会报错并停止清洗，不使用固定答案兜底。

这是单次推理示例，每次调用会重新加载模型；大量请求或服务部署应另行封装以复用已加载的模型。示例不自动训练，不改写数据文件。

## 手工分步执行（替代上面的一键脚本）

以下命令仅在选择手工流程时使用，仍按测试、验证顺序执行。

### 第一步：确认训练完成，导出各 200 条题面

```powershell
$runState = Get-Content -Raw -LiteralPath "$runDir/run_status.json" -ErrorAction Stop | ConvertFrom-Json
if ($runState.status -ne "completed") { throw "训练状态不是 completed，暂不开始评估。" }
if (-not (Test-Path -LiteralPath "$runDir/adapter/adapter_model.safetensors")) {
    throw "找不到训练后的适配器。"
}

@'
import json
import sys
from pathlib import Path

out = Path(sys.argv[1])
out.mkdir(parents=True, exist_ok=False)
for split in ("test", "validation"):
    source = Path("datasets/data_cleaning") / (split + ".jsonl")
    rows = [json.loads(s) for s in source.read_text(encoding="utf-8").splitlines()]
    assert len(rows) == 200, f"{split} 应为 200 条，实际为 {len(rows)}"
    with (out / (split + "-prompts.jsonl")).open("x", encoding="utf-8") as f:
        for row in rows:
            prompt = next(m["content"] for m in row["messages"] if m["role"] == "user")
            f.write(json.dumps({"id": row["id"], "prompt": prompt}, ensure_ascii=False) + "\n")
    print(split, len(rows))
'@ | python - $evalDir

if ($LASTEXITCODE -ne 0) { throw "题面导出失败，请检查数据和输出目录。" }
```

输出 `validation-prompts.jsonl`、`test-prompts.jsonl`，各 200 条，只包含题号和 user 需求，不包含 assistant 参考答案。预测脚本使用训练清单中的同一 system 提示。旧的 1,000 题文件不会自动缩小，必须从当前数据重新提取。

### 第二步：先测试，再验证，同时比较基础模型

下面按测试集 → 验证集的顺序执行；每个集合先微调模型、后基础模型，每次预测完成后立即评分。四次预测依次执行，不同时占用 GPU。

```powershell
foreach ($split in @("test", "validation")) {
    foreach ($mode in @("finetuned", "base")) {
        $prediction = "$evalDir/$split-$mode.jsonl"
        $report = "$evalDir/$split-$mode-report.json"

        $predictArgs = @(
            "scripts/predict_eval.py",
            "--run", $runDir,
            "--data", "datasets/data_cleaning",
            "--suite", "$evalDir/$split-prompts.jsonl",
            "--output", $prediction,
            "--max-new-tokens", "512"
        )
        if ($mode -eq "base") { $predictArgs += "--base" }

        python @predictArgs
        if ($LASTEXITCODE -ne 0) { throw "$split $mode 预测失败。" }

        python scripts/score_data_cleaning.py --data datasets/data_cleaning --split $split --predictions $prediction --report $report
        if ($LASTEXITCODE -ne 0) { throw "$split $mode 评分失败。" }
    }
}
```

全程离线，不需要 Docker 或模型 API。基础模型不加载本次 LoRA，两边使用相同基础快照、system 提示、题面、贪心生成规则和 512 token 上限。验证集用于开发与调整参数，测试集用于最终评估，不能反复根据测试结果选择配置。

预测和报告均拒绝覆盖。中途失败时先解决报错，不要直接重跑整个循环；需要全部重跑时更换 `$evalDir`，从手工第一步重新导出题面。

### 第三步：查看四份报告

```powershell
Get-ChildItem -LiteralPath $evalDir -Filter "*-report.json" | ForEach-Object {
    $evaluation = Get-Content -Raw -LiteralPath $_.FullName | ConvertFrom-Json
    [PSCustomObject]@{
        report = $_.Name
        total = $evaluation.total
        correct = $evaluation.correct
        exact_config_accuracy = $evaluation.exact_config_accuracy
        schema_valid_rate = $evaluation.schema_valid_rate
    }
} | Format-Table -AutoSize
```

四份报告为 `validation-finetuned-report.json`、`validation-base-report.json`、`test-finetuned-report.json`、`test-base-report.json`，每份 `total` 应为 200。重点比较同一集合的 `exact_config_accuracy`（参考配置匹配率）与 `schema_valid_rate`（JSON/配置结构合格率）。它们都不是验证 loss，也不是执行结果正确率。

## 历史版本与评分边界

完整旧数据保留在 `datasets/data_cleaning/archive/full_v1`，旧运行恢复时可用该目录匹配原始哈希。缩小留出集之前运行的验证 loss 属于旧 1,000 条验证集，不能当作当前 200 条集合的指标。缺少当前任务的完整模型时，按上面的第一、二步训练。

预测文件为 UTF-8 JSONL，每行包含 `id` 和模型原始 `response`。生成时只能提供样本中的 system/user 消息，不提供 assistant 参考答案。禁止把参考答案写入预测文件后当成模型成绩。

报告拒绝覆盖。缺答计入分母，重复或未知题号拒绝评分；Markdown 包裹、非法 JSON、重复键和 schema 错误都不算格式通过。`schema_valid_rate` 只评价格式，`exact_config_accuracy` 比较参考配置：忽略 JSON 对象键顺序与空白，保留数组顺序与 JSON 值类型。某些执行等价配置仍可能被严格匹配判错，所以该指标不是执行结果正确率。

基础模型和微调模型必须使用相同 system 提示、基础快照、题面和生成规则分别计分。`pyforge benchmark` 与一键脚本使用相同的数据清洗评估链路。
