# 数据清洗数据集指南

当前方向是中文需求转固定 JSON 数据清洗配置，四种操作的规则见[配置约定](../datasets/data_cleaning/配置约定.md)，来源与划分见[数据集说明](../datasets/data_cleaning/数据集说明.md)。只生成配置，真实数据由固定程序处理。

## 执行顺序：训练 → 导出题面 → 验证 → 测试 → 查看报告

当前训练 1,000 条、验证 200 条、测试 200 条。下面按顺序在同一个 PowerShell 窗口执行；重新打开窗口后，需要重新设置环境和目录变量。训练由你手动启动，训练命令正常结束后再开始导出题面和评估。

### 第一步：激活环境，设置新的输出目录

```powershell
Set-Location E:\code\github\pyforge
.\.venv\Scripts\Activate.ps1

$runDir = "outputs/data-cleaning-002"
$evalDir = "outputs/data-cleaning-eval-002"

pyforge doctor
if ($LASTEXITCODE -ne 0) { throw "训练环境检查失败。" }
```

两个输出目录必须是新目录。已存在时更换编号，例如分别改成 `data-cleaning-003` 和 `data-cleaning-eval-003`，后面的命令共用这两个变量。旧 `outputs/train-001` 是 LeetCode 模型，不能代替新任务模型；中断的 `outputs/data-cleaning-001` 也不能当成已完成的运行。

### 第二步：训练，等待正常结束

```powershell
pyforge train --config configs/train_4080.json --data datasets/data_cleaning --output $runDir --offline
if ($LASTEXITCODE -ne 0) { throw "训练未正常完成，请先检查报错。" }
```

当前 4080 SUPER 配置使用 1.5B 模型，从基础模型初始化新 LoRA，训练 2 轮、共 126 个优化器更新步。micro batch 为 1，梯度累积为 16，进度条不是样本计数。训练过程中会自动计算验证 loss；后面的验证和测试检查实际 JSON 答案。不要在训练仍进行时启动预测。

训练结束后可先查看指标：

```powershell
Get-Content -LiteralPath "$runDir/metrics.json"
```

### 第三步：确认训练完成，导出各 200 条题面

```powershell
$runState = Get-Content -Raw -LiteralPath "$runDir/run_status.json" -ErrorAction Stop | ConvertFrom-Json
if ($runState.status -ne "completed") { throw "训练状态不是 completed，暂不开始评估。" }
if (-not (Test-Path -LiteralPath "$runDir/adapter/adapter_model.safetensors")) {
    throw "找不到训练后的适配器。"
}

@'
import json
import sys
from pathlib import Path

out = Path(sys.argv[1])
out.mkdir(parents=True, exist_ok=False)
for split in ("validation", "test"):
    source = Path("datasets/data_cleaning") / (split + ".jsonl")
    rows = [json.loads(s) for s in source.read_text(encoding="utf-8").splitlines()]
    assert len(rows) == 200, f"{split} 应为 200 条，实际为 {len(rows)}"
    with (out / (split + "-prompts.jsonl")).open("x", encoding="utf-8") as f:
        for row in rows:
            prompt = next(m["content"] for m in row["messages"] if m["role"] == "user")
            f.write(json.dumps({"id": row["id"], "prompt": prompt}, ensure_ascii=False) + "\n")
    print(split, len(rows))
'@ | python - $evalDir

if ($LASTEXITCODE -ne 0) { throw "题面导出失败，请检查数据和输出目录。" }
```

输出 `validation-prompts.jsonl`、`test-prompts.jsonl`，各 200 条，只包含题号和 user 需求，不包含 assistant 参考答案。预测脚本使用训练清单中的同一 system 提示。旧的 1,000 题文件不会自动缩小，必须从当前数据重新提取。

### 第四步：先验证，再测试，同时比较基础模型

下面按验证集 → 测试集的顺序执行；每个集合先微调模型、后基础模型，每次预测完成后立即评分。四次预测依次执行，不同时占用 GPU。

```powershell
foreach ($split in @("validation", "test")) {
    foreach ($mode in @("finetuned", "base")) {
        $prediction = "$evalDir/$split-$mode.jsonl"
        $report = "$evalDir/$split-$mode-report.json"

        $predictArgs = @(
            "scripts/predict_eval.py",
            "--run", $runDir,
            "--data", "datasets/data_cleaning",
            "--suite", "$evalDir/$split-prompts.jsonl",
            "--output", $prediction,
            "--max-new-tokens", "512"
        )
        if ($mode -eq "base") { $predictArgs += "--base" }

        python @predictArgs
        if ($LASTEXITCODE -ne 0) { throw "$split $mode 预测失败。" }

        python scripts/score_data_cleaning.py --data datasets/data_cleaning --split $split --predictions $prediction --report $report
        if ($LASTEXITCODE -ne 0) { throw "$split $mode 评分失败。" }
    }
}
```

全程离线，不需要 Docker 或模型 API。基础模型不加载本次 LoRA，两边使用相同基础快照、system 提示、题面、贪心生成规则和 512 token 上限。验证集用于开发与调整参数，测试集用于最终评估，不能反复根据测试结果选择配置。

预测和报告均拒绝覆盖。中途失败时先解决报错，不要直接重跑整个循环；需要全部重跑时更换 `$evalDir`，从第三步重新导出题面。

### 第五步：查看四份报告

```powershell
Get-ChildItem -LiteralPath $evalDir -Filter "*-report.json" | ForEach-Object {
    $evaluation = Get-Content -Raw -LiteralPath $_.FullName | ConvertFrom-Json
    [PSCustomObject]@{
        report = $_.Name
        total = $evaluation.total
        correct = $evaluation.correct
        exact_config_accuracy = $evaluation.exact_config_accuracy
        schema_valid_rate = $evaluation.schema_valid_rate
    }
} | Format-Table -AutoSize
```

四份报告为 `validation-finetuned-report.json`、`validation-base-report.json`、`test-finetuned-report.json`、`test-base-report.json`，每份 `total` 应为 200。重点比较同一集合的 `exact_config_accuracy`（参考配置匹配率）与 `schema_valid_rate`（JSON/配置结构合格率）。它们都不是验证 loss，也不是执行结果正确率。

在 `E:\code\github\pyforge` 激活 Python 3.12 虚拟环境。以下 tokenizer 快照为当前本地缓存，迁移或改基础模型后替换为对应快照路径。命令只读取本地 tokenizer，不加载模型权重，不调用模型 API。

## 历史版本与评分边界

完整旧数据保留在 `datasets/data_cleaning/archive/full_v1`，旧运行恢复时可用该目录匹配原始哈希。缩小留出集之前运行的验证 loss 属于旧 1,000 条验证集，不能当作当前 200 条集合的指标。只剩旧 LeetCode 模型时，按上面的第一、二步重新训练新任务模型。

预测文件为 UTF-8 JSONL，每行包含 `id` 和模型原始 `response`。生成时只能提供样本中的 system/user 消息，不提供 assistant 参考答案。禁止把参考答案写入预测文件后当成模型成绩。

报告拒绝覆盖。缺答计入分母，重复或未知题号拒绝评分；Markdown 包裹、非法 JSON、重复键和 schema 错误都不算格式通过。`schema_valid_rate` 只评价格式，`exact_config_accuracy` 比较参考配置：忽略 JSON 对象键顺序与空白，保留数组顺序与 JSON 值类型。某些执行等价配置仍可能被严格匹配判错，所以该指标不是执行结果正确率。

基础模型和微调模型必须使用相同 system 提示、基础快照、题面和生成规则分别计分。原有 `pyforge benchmark` 面向 LeetCode Python 代码，不适用 JSON 配置，不要用原来的 20 题评估这个新方向。
