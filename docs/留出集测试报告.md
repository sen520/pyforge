# 留出集测试报告

## 测试对象与方法

测试 `outputs/train-002/adapter/`，对应 5 轮、115 步训练后验证损失最低的 checkpoint-115。基础模型为 Qwen2.5-Coder-0.5B-Instruct，SHA 为 `ea3f2471cf1b1f0db85067f1ef93848e38e88c25`。

使用冻结的 `datasets/leetcode/test.jsonl`，5 题、4 个题目分组。文件 SHA256 为 `a487fc88b2c63027405e8e2fce35b1790132c243427337a630192182f436e068`，与训练清单一致。该集合未参与参数更新或最佳检查点选择。

基础模型和微调模型使用同一量化基础模型、tokenizer、system/user 消息、贪心解码与 512 个生成 token 上限；分别禁用和启用适配器。模型输入没有参考答案、执行用例或报告。每题只生成一次，没有修改答案或根据结果重新生成。

生成代码只在 Docker 镜像 `pyforge-eval:py312-pytest835` 的受限容器中执行。函数题使用原数据检查器的独立用例；pytest 题要求对正确实现通过，并发现预设错误实现。已先对 5 题参考答案执行自检，全部通过。被测模块支持 solution 和 write_json 两种名称，因为题面没有规定模块名。

## 结果

| 模型 | 通过 / 总题数 | 本地用例单次生成通过率 |
| --- | --- | --- |
| 基础模型 | 0 / 5 | 0% |
| 微调模型 | 1 / 5 | 20% |

| 题目 | 基础模型 | 微调模型 | 微调回答的主要问题 |
| --- | --- | --- | --- |
| seed-016 最长无重复子串 | 失败 | 通过 | 函数通过现有用例，但说明误称空间 O(1)，实际字典空间随不同字符数增长 |
| seed-050 写 JSON | 失败 | 失败 | 没有创建父目录，且使用 ensure_ascii=True，不满足保留中文要求 |
| seed-053 非空行生成器 | 失败 | 失败 | 跳过了空白行，但 yield 原始行，未去掉行尾换行 |
| seed-058 按 UTC 日期分组 | 失败 | 失败 | 对输入列表调用 events.keys()，并未实现正确的 UTC 转换和分组 |
| seed-092 生成 write_json 的 pytest 测试 | 截断、代码块未闭合 | 失败 | 对正确实现的断言也不成立：期望紧凑 JSON，与正确实现的带缩进输出不符，并对 os.makedirs 提出不合理调用要求 |

基础模型 pytest 回答达到 512 token 上限；这一失败计入相同预算下的评估，不能推断其更长预算下也失败。微调模型 5 个回答均正常结束，未触及长度上限。执行器中的 runtime_error 包括断言失败，不应全部理解为代码无法启动。

本次结果只说明这 5 题上的有限用例表现，不能外推整体正确率，也不足以确认稳定收益。通过率不覆盖说明文字质量，最长子串题的复杂度说明仍有错误。验证损失降低不等于遵守接口、边界要求或代码正确率已经达标。

## 产物与复跑

机器可读报告及生成清单位于 `datasets/leetcode/metadata/holdout_train002_v1/`，记录模型/适配器/测试集哈希、检查器哈希、镜像 ID、预测哈希和逐题状态，随 Git 提交。模型权重和完整原始预测仍在忽略的 `outputs/` 中。

最终检查报告位于 `outputs/holdout-train-002-v2/`；该目录复用了 v1 的同一批原始预测，仅将 pytest 检查器改为支持两种模块名后重新执行，未重生成或修改答案。首次和最终统计一致。

在已有模型及镜像的机器上，用新的目录复跑：

```powershell
python scripts/evaluate_holdout.py generate --run outputs/train-002 --output outputs/holdout-new-001 --max-new-tokens 512
python scripts/evaluate_holdout.py score --run outputs/train-002 --output outputs/holdout-new-001
```

目前不建议只增加训练轮数后就宣称效果改善。若根据本报告针对性修改数据或参数，这批题将参与开发；最终验收应另准备新的留出题，并扩大题量。
