# 硅基流动教师数据生成

> 历史流程。当前训练数据改由 Codex 直接编写并验证，见《答案编写与检查指南》。除非用户重新明确要求，不再调用本页的外部模型生成命令。

## 配置与调用

将 `.env.example` 复制为项目根目录 `.env`，仅在本地填写密钥：

```dotenv
SILICONFLOW_API_KEY=在本地填写
SILICONFLOW_MODEL=deepseek-ai/DeepSeek-V4-Pro
```

`.env` 及其他环境文件均忽略，示例文件没有密钥。进程环境变量优先于 `.env`。密钥不作为命令行参数、不写入日志或运行清单。

请求使用 [官方 Chat Completions API](https://docs.siliconflow.cn/docs/api/chat-completions-post)：`POST https://api.siliconflow.cn/v1/chat/completions`，JSON body 包含 model、messages、stream=false、temperature=0.2、max_tokens=2048、enable_thinking=false。训练回答只取 content，不使用 reasoning_content。

首批试生成 3 题：

```powershell
pyforge generate --output outputs/teacher_v1 --limit 3
```

成功后继续生成剩余题目：

```powershell
pyforge generate --output outputs/teacher_v1 --limit 100 --workers 3
```

`--limit` 是本次最多新增调用数，已经完成的 ID 自动跳过。并发范围 1–4，默认 1。HTTP 错误不自动重试；再次执行同命令属于主动重试失败题，费用以平台账单为准。结果不确定的网络超时会阻止自动续跑，必须先核查 journal 和账单，不直接删除历史重跑。

可以加 `--skip-uncertain` 跳过结果未确认的 ID，继续其他尚未请求的题目；这不会重试该请求，汇总会列出 uncertain_ids。长响应可用 `--timeout 240`，更改等待时间不改变已冻结的生成参数。

## 断点与分组

只接受 `pyforge_original_seed_v1` 来源，阻止误用 doocs 验证题。按全量种子题的 group_id 和种子 42 在调用前固定 train/validation/test；有同组任务的记录不会跨集合。生成失败或检查不通过时不重新洗牌。若题库、模型、生成参数或系统提示改变，需要新输出目录。

每道题先记录 started，再调用服务，保存完整响应后记录 completed。journal 每次写入刷新磁盘。输出目录用锁防止多个生成进程重复付费；并发线程共享写入锁。进程崩溃后只有确认不存在活跃任务时才处理残留锁。

原始响应为 `seed-NNN.response.json`，清单为 `generation_manifest.json`，事件为 `journal.jsonl`，汇总为 `summary.json`，候选为 `candidates.jsonl`。原始响应和运行日志位于 outputs，不进入 Git；可能含有服务端返回的推理字段，候选消息中不包含这些字段。

token 用量来自响应 usage，汇总不等于人民币账单，不包含无法确定用量的失败请求。模型 ID 是请求名与响应名，服务端未公开的内部版本不能由本地保证固定。

## 检查与导出

完整停止、非空 content、存在可编译 Python 代码块才进入候选；被截断、代码错误和含显式 think 标签的响应不导出。语法通过仍标记待审核，不等于正确。

独立检查脚本为 85 道实现与修复题提供自有断言，在 Docker 中运行教师答案的首个 Python 代码块，不依赖教师自己生成的测试：

```powershell
docker pull python:3.12-slim
python scripts/verify_teacher_data.py --source outputs/teacher_v1/candidates.jsonl --output datasets/archive/teacher_v1
```

通过的样本按预先冻结 split 导出 train.jsonl、validation.jsonl、test.jsonl；未通过或需要人工审核的测试生成和解释题放在 pending_review.jsonl。失败包含实现错误、接口不符或用例适配问题，不能一概认定为模型错误，须检查原因后再决定修订哪个部分。

执行通过的回答保留首个实现与前置说明，额外测试等代码块仅保留在原始响应中，避免训练出现导入不存在的示例文件。此转换记录在 normalization 字段。审核记录包含测试脚本 SHA、输入 SHA 和 Docker 镜像 ID，支持跳过已审样本；脚本或输入变化要使用新目录。

若 pytest 测试与实现写在同一代码块，使用 AST 移除额外测试函数、夹具及 pytest 导入，保留实现函数体不变，再执行独立检查。原始响应始终保留，转换过程有记录。

自有断言不是形式化证明，仍需人工抽查，尤其是性能、完整约束、解释正确性和答案风格。数据中的 execution=true 仅表示通过本项目这些用例，human_review 不自动设为 true。数据源许可保留待确认状态，发布前单独确定授权。

最后执行数据格式校验后再启动训练，使用 2048 token 的配置时还需核对编码过滤数量：

```powershell
pyforge validate datasets/archive/teacher_v1/train.jsonl
pyforge train --config configs/train_4080.json --data datasets/archive/teacher_v1 --output outputs/train-teacher-001
```

4060 的 512 token 配置主要做小样本流程验证，可能过滤较长的正常答案；不要硬截断代码来适配。
