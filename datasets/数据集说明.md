# 数据集目录说明

当前训练数据为 Codex 直接编写、经检查的 100 题问答。三个集合统一位于本目录，通过文件名区分：

| 文件 | 条数 | 用途 |
| --- | ---: | --- |
| train.jsonl | 90 | 模型训练 |
| validation.jsonl | 5 | 验证 loss、选择训练检查点 |
| test.jsonl | 5 | 留出问答，不参与调参 |

训练命令只需指定该目录：

```powershell
pyforge validate datasets/train.jsonl
pyforge train --config configs/smoke_4060.json --data datasets --output outputs/smoke-codex-001
```

正式实验使用 configs/train_4080.json，并采用新输出目录。

## 子目录

- sources/seed_questions.jsonl：100 道原始题目，不含答案。
- metadata/codex_v1/：完整候选、作者清单、逐题执行结果、文件 SHA、编码长度报告；其中 pending_review.jsonl 为空，仅作原审核清单的配套记录，不是第四个训练集合。
- metadata/doocs_import/：原始 doocs 导入统计备份。
- benchmarks/doocs-leetcode/：3,422 道独立算法候选题及 20 题、100 用例的可执行子集，附来源和许可证；不混入训练数据。
- archive/teacher_v1/：按用户要求保留的旧版硅基流动数据，不能与当前集合合并。

已删除旧加法示例及其 train/validation/test 划分。生成工具、旧版模型响应和历史输出未删除；data/sources/ 仅保留本地上游仓库缓存，不提交 Git。

## 来源与检查

本批包含算法 40、日常编程 25、修复 20、测试生成 8、解释 7 题。全部答案由 Codex 在项目中直接编写，没有调用模型 API。答案源代码位于 scripts/codex_solutions.py 与 scripts/codex_review_answers.py。

100 题已通过本项目 Docker 检查：85 道实现通过独立用例，8 组 pytest 测试通过正确实现并各检测到一个指定错误实现，7 道解释题的示例断言通过。按 group_id、种子 42 预先划分，题族不跨集合。目录迁移保留了三个数据文件原始字节和 SHA，不重新随机划分。

当前 metadata 清单保留答案生成和验证时的源文件 SHA；后续脚本仅调整默认路径，原执行版本可从 Git 提交 94240d6 追溯。候选与最终集合是同一批题的不同状态，不能合并重复训练。

用本地 Qwen2.5-Coder-0.5B-Instruct 模板检查后，100 条均不超过 512 tokens，最长 364。更换模型时需要重新验证模板和长度。

执行通过不等于对所有输入、复杂度或解释做了形式化证明，human_review 保持 false。验证和留出各仅 5 条，不能用于可靠的全面能力结论。许可证仍保留待确定状态。

离线重建与检查见 docs/答案编写与检查指南.md。
