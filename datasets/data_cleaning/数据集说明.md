# 数据清洗配置数据集

任务：将明确的中文数据清洗需求转换为纯 JSON 配置。仅支持去重、删除空值、筛选、排序，语义和字段约定见[配置约定](配置约定.md)。

## 数据与来源

当前使用 1,000 条训练、200 条验证、200 条测试，共 1,400 条。原始三个集合各 1,000 条的完整版本保留在 `archive/full_v1/`，逐条作者原稿仍完整保留。

| 文件 | 条数 | 最长完整对话 token |
| --- | ---: | ---: |
| `train.jsonl` | 1,000 | 425 |
| `validation.jsonl` | 200 | 411 |
| `test.jsonl` | 200 | 413 |

长度使用本地 Qwen2.5-Coder-1.5B-Instruct tokenizer 实测，包含 system/user/assistant 与聊天模板，全部低于 2,048 token，未过滤样本。文件 SHA256、操作分布与检查详情见 `metadata/manifest.json`；构建脚本要求作者原稿每集至少 1,000 条；当前默认保留训练集，分别抽取 200 条验证和测试。

- `sources/train_authored.jsonl`：Codex 训练子代理逐条编写的需求与答案。
- `sources/validation_authored.jsonl`：Codex 验证子代理逐条编写的需求与答案。
- `sources/test_authored.jsonl`：Codex 测试子代理逐条编写的需求与答案。
- `sources/validation_authored.tsv` 保留验证集的直接作者紧凑手稿，已逐条核对与 1,000 条 JSONL 的需求和答案一致。
- `train.jsonl`、`validation.jsonl`、`test.jsonl`：封装为项目标准 messages 格式的数据。
- `metadata/manifest.json`：作者、原稿/数据哈希、自动检查与分布统计。
- `metadata/semantic_review.json`：若存在，记录主代理抽查与独立用例，不代表所有样本完成执行验证。

用户明确授权三个子代理并行编写。需求、列名、条件值、操作顺序与答案参数由模型逐条直接书写；紧凑记法的固定键展开、JSON 序列化、计数和检查由代码完成。未使用循环模板、参数替换或其他模型 API 批量生成训练内容。源文件与封装文件同时保留。作者是 Codex，自动检查不标为人工审核，项目尚未另授数据许可证。

## 划分

三个集合预先分配不同业务领域，不把同一领域的改写随机分散到训练与留出集合。

| 集合 | 场景领域 |
| --- | --- |
| train | 电商订单、仓储库存、会员账户、商品目录、客服工单 |
| validation | 图书馆借阅、校园课程、博物馆馆藏、展会报名、剧院票务 |
| test | 气象观测、设备巡检、物流配送、农场采收、运动赛事 |

同场景族使用相同 group_id。统一检查 ID、场景族、完全对话及规范化题面重复；基础四种操作语义在各集合共享，未宣称完成所有语义近似去重。验证集用于开发，测试集不得用于训练或选择超参数。按用户后续要求缩小验证与测试集：每个场景固定保留 40 条，每种操作序列至少一条，剩余名额按层容量用最大余数法分配，层内使用固定 SHA256 排序。保留原始 ID、source_line、题面和答案，不改写或重新编号。选择不读取任何模型预测或得分，具体 ID 与分布见 manifest。该抽样优先覆盖操作组合，不是原始 1,000 条分布的严格等比例样本。

## 检查边界

全量检查格式、答案 schema、列名是否在题面出现、重复/泄漏及本地 tokenizer 完整对话长度。长样本直接报错，不静默过滤。原稿与最终 answers 保持一致，不用检查器反向生成答案。

配置执行器只解释四种允许操作，不执行 Python 或其他任意代码。执行器单元测试验证空值、比较边界、真假值与数字的区别、稳定排序和操作顺序；这不等同于全部中文需求的语义正确性或模型执行通过率。每条训练记录的 execution 保持 false；主代理曾从完整作者原稿中实际抽读 139 条需求与答案，记录在 `metadata/semantic_review.json`。另为完整原稿中的 18 条参考配置直接编写输入行及预期保留行，18 条均通过，记录在 `metadata/execution_cases.json` 和 `metadata/execution_review.json`。这两个数字均不代表全量语义或执行证明。

当前默认训练和评估只读取本目录的数据。安装、构建、训练与评分命令见[数据清洗数据集指南](../../docs/数据清洗数据集指南.md)。

## 已有训练与评估

缩小留出集时训练文件字节和哈希保持不变，因此使用相同训练数据完成的模型可以直接评估当前 200 条测试题，不必重新训练。当前示例使用已完成的 `outputs/data-cleaning-002`；中断的 `data-cleaning-001` 不能当作已完成模型。原运行的验证 loss 对应旧 1,000 条验证集，不应解读成当前小集合的指标。恢复旧运行必须使用原数据哈希，可指定完整快照 `--data datasets/data_cleaning/archive/full_v1`。

推荐使用 `scripts/benchmark_data_cleaning.py --run outputs/data-cleaning-002 --output outputs/data-cleaning-comparison-001` 一次完成验证、测试、基础/微调对比和 Excel 导出；已有四份完整预测时加 `--reuse-predictions outputs/data-cleaning-eval-002` 并使用新输出目录。Excel 保留原始回答，严格与去代码块外壳的诊断分开显示。完整命令、文件要求和依赖见指南。

已导出的旧 `prompts.jsonl` 和预测不会随数据集缩小；重新从当前 test.jsonl 提取题面，并使用新的评估输出目录。不要直接把旧 1,000 条预测交给当前 200 条评分器，它会拒绝未知 ID。
