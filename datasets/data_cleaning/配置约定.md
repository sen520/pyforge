# 数据清洗配置约定

输入为中文需求，列名用反引号或引号明确标记。输出仅为 JSON 对象 `{"steps":[...]}`，不得输出 Markdown 或解释。按中文需求指定顺序执行，各步只能包含下述字段。

- 去重：`{"op":"deduplicate","columns":["email"],"keep":"first"}`；keep 只能 first / last，按列组合判重，保留行仍保持原相对顺序。
- 删除空值：`{"op":"drop_null","columns":["age"],"how":"any"}`；any 表示任意指定列为 null 则删除；all 表示全部指定列为 null 才删除。空字符串、0、false 不等于 null。
- 筛选保留：`{"op":"filter","column":"age","operator":"ge","value":18}`；operator 只支持 eq、ne、gt、ge、lt、le、in、not_in。in/not_in 的 value 是非空数组；其他为非 null 的字符串、数字或布尔值。比较区分类型，布尔值不等于数字。任意筛选都删除该列为 null 的行，包括 ne/not_in。
- 排序：`{"op":"sort","by":[{"column":"age","ascending":true}]}`；支持多列优先级与独立升降序，稳定排序，null 始终在最后。列内非 null 值类型一致。

每个需求必须有明确答案，只用上面四种操作；不需要推测字段名或增加隐含操作。支持一步至多步。数值和字符串值的区别应在题面明确。不得用代码模板、替换列名/阈值的循环、笛卡尔积生成需求和答案。

作者直接编写的来源行格式为 JSONL：`{"prompt":"中文需求","answer":{"steps":[...]},"group":"场景族英文标识"}`。每行需求及答案由模型直接书写；构建脚本只序列化、校验和加元数据。train、validation、test 各自使用不同场景族，同族改写不能跨集合。

执行检查是自动化校验，不是人工审核，也不是自然语言语义正确性的证明。静态检查与执行检查分别报告。来源和所有检查状态必须真实记录。
