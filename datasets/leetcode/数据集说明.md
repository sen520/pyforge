# 数据集目录说明

默认三个集合位于同一目录，训练入口仍使用 `--data datasets/leetcode`：

| 文件 | 条数 | 组成与用途 |
| --- | ---: | --- |
| train.jsonl | 2,292 | 原有 90 条 + 新增 2,202 条，更新参数 |
| validation.jsonl | 129 | 原有 5 条 + 新增 124 条，计算验证损失与选择检查点 |
| test.jsonl | 123 | 新划出的独立题目，不参与参数更新或检查点选择 |

新增共 2,449 道 doocs 题及已有 Python 参考答案。旧版 100 条数据的原始文件完整保留在 `archive/codex_v1/`；其中旧 5 条测试已用于结果分析，本次仅存档，不进入新划分。旧版硅基流动数据继续保留。

## 来源与检查状态

- 原始 Codex 数据：由 Codex 直接编写，100 条曾通过 Docker 检查；本次复用训练 90 条、验证 5 条。
- 新增 doocs 数据：来自上游提交 `757ae31a437dc98972e73057f122a7c947acf8d7` 的既有 Python 题解，不是 Codex 原创，也没有调用模型 API。
- 新增答案通过语法、可识别标准库依赖和完整对话长度检查；`verification.execution=false`、`human_review=false`，**尚未逐题执行验证**。静态检查不能保证算法、复杂度或边界行为正确。
- 题面与上游答案保留 source_path、source_url、source_sha256、作者归属和 CC-BY-SA-4.0 标记。许可证副本位于 `metadata/doocs_sft_v1/LICENSE`。没有复制上游思考过程；答案只含代码，必要时补全标准库导入。

新增数据以题号为题族，并将相同实现 AST 的题目合并成同一题族，使用种子 42 分为约 90%/5%/5%。原始种子题对应的 47 个已知相同/近似主站题在旧导入时已排除。20 道可执行算法评估题也不参与此次新增划分。当前仍不具备完整语义去重保证；公开题还可能出现在基础模型预训练中。

## 训练命令与长度

```powershell
pyforge validate datasets/leetcode/train.jsonl
Set-Location E:\code\github\pyforge
pyforge train --config configs/train_4080.json --data datasets/leetcode --output outputs/train-4080-001 --offline
```

新增问答使用本地 Qwen2.5-Coder-0.5B-Instruct 的原生模板检查，长度为 194～1,940 token，构建上限为 2,048；仅 858 条新增问答不超过 512 token。当前 4080 SUPER 请使用 `train_4080.json`（1.5B、2048 token、2 轮，尚未完成实测），否则 smoke 的 512 token 限制会过滤很多新增样本。历史 `train_4060.json`（0.5B）已完成本机 1,146 步训练，记录见 reports/train-doocs-001；显存需求仍随实际长度和设备变化。

4080 SUPER 使用 `configs/train_4080.json`，需先下载对应 1.5B 模型，并重新核对其编码统计。两者都必须使用新的输出目录，不能用新数据恢复旧检查点。

## 子目录与复现

- `sources/seed_questions.jsonl`：原始 100 道种子题。
- `metadata/codex_v1/`：历史作者、候选、执行与编码记录，哈希对应 `archive/codex_v1/` 的原始三个文件。
- `metadata/doocs_sft_v1/`：首次扩充的历史清单、排除原因、原始 SHA、上游版本、构建脚本 SHA、许可证。
- `metadata/current_manifest.json`：当前三个集合的数量和 SHA；`metadata/interface_repair_v1/` 保存训练/验证 57 条主接口修复的完整差异，答案与划分不变。
- `benchmarks/doocs-leetcode/`：3,422 道历史题面来源及 20 题可执行评估子集。完整目录已部分用于训练，不能整体再算独立评估集；20 题仍单独保留。
- `metadata/holdout_train002_v1/`：旧 5 题测试的模型对比报告。
- `archive/codex_v1/`：扩充前的 train/validation/test 原始字节。
- `archive/teacher_v1/`：旧硅基流动数据，保留但不混入当前划分。

模型、原始评估预测和本地上游仓库仍不提交 Git；默认三个数据文件与上述元数据提交 Git。离线重建、过滤规则与新旧数据边界详见 [训练数据扩充说明](../../docs/训练数据扩充说明.md)。
